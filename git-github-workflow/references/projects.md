# 开发总看板与 README 协作入口

新建 GitHub 仓库时默认执行；用户明确要求为既有仓库补建、关联或完善模块/视图与 README 入口时也执行。本技能更新本身不创建真实看板，不批量改造已有仓库。

## 查找与复用

1. 读取当前项目 `AGENTS.md` 中的看板链接、owner、字段映射、事项分类及权限约定，再检查仓库已关联的 Projects 和已知候选看板。已存在明确的项目总看板时直接复用，不因名称不符合新默认值而重建。
2. 检索须基于目标仓库的 owner 和真实关联。新仓库已由某个跨仓库总看板覆盖时，按既有约定关联和复用，不强制每个仓库另建一块。同名且关联不明的候选不能随便选，先查明；无法确定唯一目标时仅澄清这一点。
3. GitHub Projects 属于个人账号或组织，与仓库的创建、可见性及权限分别管理；仓库的 Projects 功能开关不表示看板已创建或已关联。使用可用连接器、已认证 CLI 或官方 GraphQL 能力验证，不以能够写 Issue 推断能够管理 Projects。

## 没有可复用看板时

- 在目标仓库的同一 owner 下创建 `<项目名> 开发总看板`，默认私有，关联仓库；项目另有明确名称或可见性约定时沿用。需要设置默认仓库时核对为本仓库，不能改动已有跨仓库看板的默认仓库。
- 新看板默认使用“待处理、处理中、待验证、已完成”四种任务状态和按状态分组的开发视图。实现视图所需的工具能力不可用时如实记录缺少的界面配置，不把仅有 project 对象当成全部完成。
- 既有看板沿用真实字段、选项、模块、视图和内建自动化；用语义映射识别 Todo/In Progress 等状态，不擅自重命名或重置选项、批量改动条目。新看板核对关闭/合并与 Done 的内建规则，避免在必要验收未完成时因状态或 PR 合并而误关闭 Issue。
- 默认采用 Hub 的收录粒度：重要功能、规划和阶段目标进入总看板，普通小 Bug、文案和局部调整留在 Issues。已有项目采用其他分类时保留。不要默认导入全部历史 Issues、启用无过滤的 auto-add 或将普通修复全部加入看板。
- 将看板链接、owner/标识、仓库关联、状态含义和事项分类写入本项目 `AGENTS.md`；记录“明确交办任务后更新进度”的授权范围，保留该项目已有更具体约定。只记录用户已选择的默认工作流，不增加自动挑选待办或发布权限。

## 根据项目功能配置模块与视图

- 先阅读 README、已有规划、源码目录和相关实现，提取有证据的产品功能与维护边界。按用户可识别的功能组织少量清晰模块，记录模块与源码/文档的对应关系；不要机械地每个目录一个模块，也不把参考项目分类、尚未交办的设想或通用营销词当作当前产品功能。
- 优先沿用既有模块字段、选项、视图和过滤规则。补缺时先比较真实配置，保留字段/选项身份与已有条目值，不为套用新名称重建或覆盖。跨仓库看板只配置本项目范围内确有必要的视图，不改动其他项目的分类。
- 尚无适用分类时，通常新增单选“模块”字段，以当前实际功能为选项。保留不带模块过滤的总看板；按模块建立有实际用途的筛选视图，默认 Board 布局、按既有状态分列，过滤表达式须使用真实字段与选项。项目很小时可只保留总视图；模块增多或功能重叠时按用途选择视图，不强制每个模块一张，也不堆砌空模板。
- 创建/修改前查询同名与等价视图，能复用则复用。回读每个视图的名称、布局和过滤条件，核对能指向目标模块。工具无法完成的配置明确报告为未完成，不用只有名字的视图冒充已配置筛选。
- 将实际模块含义、字段标识、总视图与模块视图链接记录在项目 `AGENTS.md`。新收录事项按实际功能归入已有模块；跨模块事项选择主要模块并说明关联，分类不确定时先核对需求。已有事项只有在本次范围内且证据充分时才补分类，不批量移动无关事项，也不为填满新模块虚构功能 Issue。

## README 开发协作入口

- 在本地 README 的项目简介之后、长篇能力介绍或更新日志之前，添加或原位更新一处简洁导航：`Issues · 开发总看板 · 项目协作规则`。Issues 链接指向真实仓库，看板使用已验证的总视图，协作规则优先使用仓库内 `AGENTS.md` 相对链接；不重写无关内容，不重复插入导航。
- 紧接一段简短中文说明：修改任务完成并通过必要检查后，默认自动中文提交并同步 GitHub，用户明确的项目例外优先；重要功能/规划与普通 Bug 的收录遵循当前约定；整理规划不代表开始实现；发布时机由用户决定。README 与 `AGENTS.md` 中的默认约定或项目例外保持一致，不通过这段文字扩大权限。
- 项目已有计划索引、资料清单、贡献指南等有用入口时，沿用其真实链接；不要给所有项目硬塞相同的文档栏目。缺少协作规则文档时先记录本次实际授权和项目配置，不创建没有内容的占位文件或失效链接。
- 保留 README 原来的产品说明、语言及维护结构。核验本地相对路径、远程目标身份和看板可访问性；私有看板受项目权限限制，不能为让链接公开可读改变可见性。

## 核验与部分失败

回读确认看板身份、真实仓库关联、可见性、状态、模块与视图及项目文档记录；核对 README 导航真实有效、无重复入口且约定与 AGENTS 一致。返回实际看板链接。已有跨仓库关联须保持原状。权限或工具不足时继续独立的仓库检查/初始化，明确分别报告仓库、看板、模块视图和文档各阶段结果，保留创建成功的标识以供恢复；先回读再重试，不因配置失败反复创建。
