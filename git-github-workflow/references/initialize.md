# 项目初始化与 GitHub 接入

只在当前请求包含初始化、关联或配置版本管理时读取。已是仓库时补齐缺失步骤，不重新初始化或复制参考项目。

## 先检查，再写入

1. 检查项目说明、目录用途、构建清单、锁文件、源码/资源、安装脚本、本地运行数据、历史副本和大文件。先界定真正的源码范围，再决定忽略什么。
2. 判定 Git 状态：不存在仓库、当前目录是仓库根、属于父仓库、worktree 或已有独立子仓库。父仓库存在时不能默认在子目录再建一层；detached HEAD、冲突或正在进行的 Git 操作需先按任务处理，不能当作普通初始状态。
3. 阅读已有 `.gitignore`、`.gitattributes`、`AGENTS.md`、检查/发布脚本和 `.github/workflows`；检查有效 Git 配置与来源、提交身份、钩子、远程及当前上游。远程 `.git/config` 不属于 GitHub 版本文件，不能声称仅查看远程源码就已取得其本地配置。
4. 验证可用 GitHub 认证账号及目标 owner/name、权限与可见性。先检查同名远程仓库是否存在；对 401/403/404，结合认证与目标访问权限判断，不直接将权限问题解释为“仓库未创建”。

## 参考已有项目

用户指定参考仓库时，读取其当前元数据、`AGENTS.md`、忽略规则及真实存在的自动化文件。没有指定且可访问时，可只读参考 `VondeSong/hub-search`；读取失败则使用已验证的本地项目证据，明确参考未读取，不阻塞独立检查。

以目标项目的技术栈和用途选择适用规则，不能整套复制：

- 通常排除依赖缓存、构建/分发产物、日志、备份、本机工具状态、环境凭据及运行数据库；保留源码资源、应版本化的锁文件、安装脚本和脱敏示例配置。
- 根据目录用途增加精确规则；例如本地历史副本可忽略，真正维护的源码归档不能仅因名为 `archive` 就排除。数据库 fixture、公共证书、工具包装文件等需按内容判断，避免过宽后缀规则丢失源码依赖。
- 保留已有 `.gitignore` 及例外，使用候选文件清单、`git check-ignore` 和初次暂存差异核验。忽略规则不会自动移除已跟踪文件；移除跟踪及历史敏感内容是另行处理的问题，不能悄悄重写历史。
- 将 `AGENTS.md` 的自动提交约定、本地检查脚本和 GitHub Actions 分开辨认。参考项目没有 `.github/workflows` 时，如实说明，不把普通脚本称为已启用 CI，也不擅自新增工作流、钩子、分支保护或标签体系。
- 新建个人仓库默认私有；已有仓库保留用户既有可见性。不要因参考项目私有就悄悄改变现有公开项目，也不要从它的设置推断通用权限或当前账号支持的付费功能。

## 初始化或补齐关联

- 确认目标目录不属于现有仓库后，才初始化。全新项目没有约定时使用 `main`；现有分支名与历史保留。
- 复用有效的提交身份；确需补充时只设置项目级 `user.name` / `user.email`。可从已验证账号使用其姓名和 GitHub noreply 邮箱；身份无法确定时再询问，不填写虚构邮箱，也不复制参考作者身份。
- 新仓库名称优先沿用用户指定名称，否则从项目目录/清单推断，并核对认证账号。创建远程时不自动生成 README、许可证或初始化提交，以免与本地已有历史冲突。
- 远程已存在时先确认其确为本项目：空仓库可以关联；已有历史则获取并比较祖先关系。不能覆盖不相关仓库、对非空远程盲目推送或自动强推。
- 已有 `origin` 或其他远程时保留，核对 fetch URL、push URL、`pushRemote` / `pushDefault` 与上游，不擅自改指向新仓库。只有目标明确时才添加缺少的关联和 tracking。
- 首次提交前，检查最终候选文件的大小、敏感信息及忽略效果，只提交确认的项目文件。检查按初始导入实际影响执行，不把未运行的应用测试写为通过。提交与首次推送沿用主文件的中文保存流程。
- 新建 GitHub 仓库时，默认按 [看板与 README 协作入口](projects.md) 创建或关联看板，根据实际功能配置模块与视图，并补齐 README 的 Issues、开发总看板和项目协作规则导航；把实际链接、字段映射与授权写入本项目 `AGENTS.md`。若只是关联既有仓库，先沿用其既有看板和约定；当前任务未要求补齐时，不对全部老仓库批量改造。
- 用户要求长期沿用时，将项目参数及实际授权合并进该项目 `AGENTS.md`；已有授权直接保留，不为同步通用流程而删除授权。hub-search 的具体看板、模块分类与仅规划授权不可复制到其他项目；明确交办任务的通用执行规则见 [任务执行流程](issue-workflow.md)。

## 验收

核对本地根目录、分支、远程与 tracking、GitHub owner/name 和可见性、初始文件清单及远端提交。新建仓库还需回读看板的身份、关联、可见性、模块视图和项目文档记录，核对 README 开发协作入口。分别报告各阶段已完成和未完成的部分；有其他未提交文件时说明归属，不为达成“干净”而清理用户文件。
