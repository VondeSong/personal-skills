# 索引与案例内容

归档、补索引或按字段查询时读取。键、类型和选项取实时 schema；此处只定义语义。

## 字段

保留名称、类型、适用场景、视觉特征、原始来源、验证范围。新增五字段使用文本，多个词用 `；` 分隔，便于组合范围和必要限制；复用已有词，不为每个案例改 schema。

| 字段 | 内容与边界 |
| --- | --- |
| 平台 | 证据呈现的平台，如桌面 Web、Android、macOS 风格桌面。未确认实现时不称原生；手机模型不等于 App 主参考 |
| 页面用途 | 运营工作台、交易审核、批处理总览、人物图库、营销落地页等；区别于泛化行业词 |
| 可借鉴模式 | 可解决的问题，如批处理进度、审核侧栏、筛选反馈、预测区间、分组导航、深色主题。反例模式明确注明反例 |
| 参考范围 | 可多值：整页结构；局部组件；配色字体；展示构图；展示动效；反例评审。静态拼贴不证明动效 |
| 素材可用性 | 细节可辨／仅构图／待复核／仅来源线索，附范围与核验依据。仅覆盖可见部分，不以已归档代替清晰度核验 |

“类型”保留合集主分类，“参考范围”表达可采用的多个方面。“验证范围”保留仅截图／已浏览／部分交互实测，正文解释具体证据。它与素材可用性独立：浏览过的视频也可能模糊，清晰截图也不能验证交互。

旧记录补索引时，有明确历史检查可写“细节可辨（依据既有核验；范围……）”；否则写待复核，不凭标题中的“高清”升级。后续检索命中仍须本次查看原图。

## 案例内容

首张实际 UI 图用于图库识别。其后用短段落说明**解决的问题、适用场景、采用范围和主要限制**。已有合适摘要就复用；没有时补紧凑的“检索摘要”，保留首图及图注，不移动媒体或复制长分析。

摘要负责定位，正文围绕最有价值的采用判断补充机制与条件，按技能正文的“分析与采用判断”展开；不按控件逐项盘点，也不强制所有标题齐全。关键结论就近对应原图、视频帧时间或页面位置，让读者能回看依据。

UI 与展示包装、静态与交互、原站值与适配值、用户偏好与 AI 分析须能区分；来源、日期、像素尺寸、帧时间和原件／预览身份集中记录，避免每段重复。已完成检查与建议验证分别说明；未实测的收益保留为推断或待验证项。

图库不能用分析页面截图代替原始 UI。多页演示只收有独立价值的稳定帧，不凑固定数量。一个页面的多个模块通常不另建重复记录。

详细检查记录按需放在子页或附件，正文保留影响采用的证据与限制。逐帧目录帮助定位，不等于每帧原尺寸精读；档案完整度与设计洞察分别判断，不以附件数量替代分析质量。

## 查询示例（决策示例，不是固定结果）

| 任务 | 匹配与边界 |
| --- | --- |
| Android 批量清理进度 | 查批处理进度、分类摘要、结果列表；桌面工具可给局部模式，不替换 Android 导航 |
| 桌面交易审核 | 查审核侧栏、筛选与状态、逐项处理，再看密度和证据；不只找绿色 |
| 仅指定 Homebrew 配色 | 查主题及配色证据；保留布局与字体，未指定部分不迁移 |
| 严格还原本轮图 | build-design 使用指定图；用户未要求时不额外找风格 |
| 模糊视频做精细还原 | 找可获取的同源清晰素材，否则限于构图，不补造细节 |
| 收藏组件库链接 | 定位资源库，记录用途和来源，不声称已提取整站系统 |

同义查询可跨语言，如审核／review、批量任务／batch progress；结合正文限制，不能让一个词同时承担行业、风格与证据等级。
