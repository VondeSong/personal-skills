# Craft 共用排版规范

汽车版与通用版共用此文件；这里只决定如何呈现，不改变执行者、空间、授权与专业判断。新页、重大追加、案例、流程、索引，或计划使用原生强调、折叠、图表等特有样式时读取。短追加继承目标局部风格。

## 成品目标与编辑顺序

先让内容讲得清楚，再用 Craft 原生层级和样式帮助浏览、理解和回顾。样式可以丰富，但每种选择应有明确用途：突出重点、表达关系、收纳次要细节或提供导航。无需把所有功能放进一页，也不要把普通工程学习笔记写成审查表。

1. 确定阅读顺序和正文结构，保留关键事实与边界。
2. 在最需要的地方选择原生表达，不能只用加粗或符号假装原生块。
3. 按当前连接实际能力实现，并分别校验内容、块属性和可见效果。

截图和 Craft 界面用于识别视觉目标；写入能力以当前 MCP 帮助/schema 或 API 输入契约为准。具体语法及降级处理读取 [共用块格式](craft-blocks.md)。

## 原生样式如何选

| 阅读需要 | 优先考虑的 Craft 表达 | 使用边界 |
| --- | --- | --- |
| 识别主题与章节 | 页面标题、标题/副标题层级、正文、说明文字 | 页面已有标题时正文不重复；章节层级连续，说明样式用于图注和来源 |
| 快速找到主旨 | 焦点或块强调/callout | 短主旨可用焦点；摘要、方法提示、风险可用块强调；不要每段加框 |
| 看清关键词 | 加粗、局部高亮、语义色 | 强调短语或差异，避免整段彩色和反复叠加样式 |
| 查看补充细节 | 折叠列表 | 收纳长示例、推导、扩展来源和补充证据；摘要、必做步骤、风险和关键适用条件保持展开 |
| 执行与检查 | 有序列表、无序列表、任务块 | 顺序用编号，并列用项目符号；只有实际需要完成或勾选的事项才创建任务 |
| 浏览独立主题 | 子页面与卡片 | 卡片应打开有实质内容的子主题；普通段落或一条补充不用卡片 |
| 对照同类属性 | 表格 | 通常保留约 2–4 个关键列；长叙述用小节，宽数据拆表或保留原附件 |
| 维护重复记录 | Collection | 用于有字段、筛选、状态或持续更新需要的记录；一次性小表不升级成数据库 |
| 理解流程与关系 | Mermaid | 流程、状态、时序或简单结构；只画来源支持的关系 |
| 探索空间布局或知识地图 | 可编辑 Whiteboard | 适合需要自由布局的结构梳理；不机械复制正文为节点 |
| 阅读数学关系 | 原生 TeX 行内/块公式 | 短变量嵌入正文，重要公式独立展示；附近解释符号、单位与适用条件 |
| 保留技术原文 | 代码块、行内代码 | 用于代码、命令、报文、标识符和字面值；不把普通中文正文包进代码块 |
| 看懂实物与原始材料 | 图片、图注、附件、描述性链接 | 图紧跟对应现象或步骤；原文件保留来源，不以文件名文字冒充附件 |
| 分隔内容组 | 轻分隔线，按场合选装饰分隔 | 概念转换处才分隔；Washi 等可用于学习页或主题页，避免每个标题后重复 |
| 建立页面气质 | 字体、卡片背景、封面、页面背景 | 继承现有风格；新页或设计任务中可有目的地采用，不能影响可读性 |

界面名称与接口字段的实测对应见 [共用块格式](craft-blocks.md)。焦点是视觉强调，可用于自己的判断；真实引文另须注明来源，不能因为接口使用 `quote` 就把自己的总结包装成来源原话。

### 文字层级与装饰

| 样式 | 用途与选择条件 |
| --- | --- |
| h1（界面左上“标题”） | 长文的主要部分；页面已有标题，普通短笔记不再重复 h1 |
| h2（副标题） | 常规知识页的主要章节；这里的“副标题”是块级样式，不必作为页面标题的副句 |
| h3（界面右上“标题”） | 章节中的子主题，保持与 h2 的从属关系 |
| h4（小标题） | 局部小节或短标签组；层级过深时优先简化结构或拆分主题 |
| body（正文） | 完整解释、依据、条件和推导；不因一句话重要就升为标题 |
| caption（说明） | 图注、出处、版本、补充说明；关键限制仍用正文并就近显示 |
| 焦点 | 单一主旨或一两句关键判断，左侧竖线引导视线；不承载长篇说明 |
| 块 / callout | 需要整体阅读的摘要、条件与提醒；多个相关段落可共用一套颜色，不给每句单独套框 |

以上中文按钮与 h1–h4 的对应在 2026-10-29 Windows Craft 实测；本地化名称可能变化，以实际回读为准。正常文档不必用完所有层级。焦点和块选其中最合适的一种，不默认叠加；无特别阅读需要就保留正文。

## 视觉语法

- 开头让读者知道主题、用途或核心结论；有帮助时给一个简短的摘要/目标强调块，不强制所有短笔记添加摘要。
- 大节优先 h2，小节 h3；追加时服从目标局部层级。正文保持自然段，不把每句话都拆成清单或标题。
- 默认左对齐正文。居中可用于短封面标题或独立公式，长中文正文不为装饰强制居中或两端对齐。
- 正文继承页面字体；等宽字体用于技术字面值。不要在同一页随意混用多种正文字体。
- 留白由段落、层级和必要分隔构成，不堆空块。颜色是第二提示，不能单靠颜色表示风险、结论或来源。
- 全页用稳定主色，风险按需要例外；普通内容保持中性。没有既定配色时可参考下表，不要求全部使用。

| 含义 | 建议色 | 必要文字语义 |
| --- | --- | --- |
| 定义、方法、说明 | 蓝色 #2563EB | 定义、说明、方法等 |
| 有依据的结论或建议 | 绿色 #15803D | 结论、建议；仍保留适用条件 |
| 条件性风险或提醒 | 橙色 #D97706 | 注意、风险 |
| 有依据的高风险、禁止、失败 | 红色 #DC2626 | 高风险、禁止、失败 |
| 来源、版本、不确定性 | 灰色 #64748B | 来源、版本、待确认 |

不要把缺资料一律画成红色警报，不用绿色把推断包装成已验证。关键边界与相关结论一起显示，完整出处和长证据可放文末或折叠。

色值是语义色种子，不是背景填充承诺：无装饰块的 `color` 作用于文字，callout 会按客户端渲染为浅底色和相应文字。块色可由接口生成深色变体；复制既有配色时保留 `color` 与 `colorDark`。页面背景、文字色应成对考虑明暗模式，不能用一组浅色背景和白字覆盖两种模式。未测试深色模式时明确说明。短语高亮与整块颜色分开使用，灰色说明不能让必要条件难以辨认。

### 子页面与卡片：先决定内容，再选择外观

正文中的一条对象名称、来源行号或检查点保留为列表/表格。主题有明确的独立阅读用途和实质内容、且现有页面不适合承载时，才创建子页面；已有正式页面优先链接，不为卡片复制知识。能被引用或未来可能扩充，并不足以单独支持建页。子页面是内容容器，卡片是它在父页的呈现方式：普通页面入口适合密集目录，卡片适合少量主题导航或需要摘要/图像辅助识别的入口。

卡片分别选择规格、预览和背景；三者相关但不能假定任意组合均可用。

| 规格（配置面板从左到右） | 编辑建议 | 当前实现边界 |
| --- | --- | --- |
| 第 1 种：图标＋摘要的紧凑卡 | 简短主题目录、少量导航入口 | Windows 界面实测仅有图标/表情两种预览入口；读回布局不能可靠区分它与第 4 种 |
| 第 2 种：紧凑内容缩略卡 | 并列主题，有少量内容或图像可预览 | MCP `small` 已实测 |
| 第 3 种：较高的内容缩略卡 | 需要更大预览面积的并列主题 | MCP `square` 已实测；名字不是实际正方形的保证 |
| 第 4 种：全宽横卡 | 章节入口、需要同时看到摘要与预览的主题 | MCP 写入 `regular` 已实测 |
| 第 5 种：全宽大卡 | 少量重点方案、案例或专题入口 | MCP `large` 已实测；避免整页连续大卡压低信息密度 |

规格按内容和当前可用菜单选择，不按名称臆测几何比例。关于第 1 种读写不对称，见共用块格式；不得为了保留样式盲目回写读回的布局值。

| 预览 | 使用条件 |
| --- | --- |
| 标准 | 知识摘要和一般主题默认；子页开头写有信息量的摘要，检查不是空白占位 |
| 表情 | 导航识别、轻量主题；不能用表情取代准确标题或风险状态文字 |
| 书本 | 长篇参考、手册或完整学习材料；不要暗示笔记具有正式标准的效力 |
| 便笺 | 简短备忘、提示和阶段性想法；正式工程要求优先标准预览 |
| 图库 | 子页内确有代表性图片的案例或方案；无图片不选图库，不拿装饰图冒充实物证据 |
| 无预览 | 标题足够明确、希望减少视觉噪声的入口；正文仍必须存在 |

不同规格能选的预览以当前面板为准；接口未暴露的选项可在已有排版授权内用界面设置，并记录“UI 完成”。不能把 Collection 的 gallery 预览参数用于普通卡片。

卡片背景默认中性或无背景；同级主题可采用一致的浅色，保持标题可读。实物图、方案图只在能帮助识别时作为背景，技术标注和尺寸仍放正文图片。页面背景、页面封面、卡片外壳背景和内容缩略图底色是不同层次；先确认改动对象，不能把页面 `backgroundColor` 当成卡片外壳色。Unsplash 可用于有明确需要的专题封面，不作为工程证据。更新已有页面不顺便改变整套主题。

### 插入形态与合集视图

| 内容需要 | 选择 |
| --- | --- |
| 一次性同维度比较 | 普通表格；长解释放正文，避免宽表 |
| 字段一致，需要筛选、排序、多视图或关联知识的记录 | Collection 的表格视图；静态清单也可使用，不要求一定有流程状态 |
| 主要通过图片识别记录 | 同一 Collection 的图库视图；卡片正文/图片有内容，显示必要名称和状态 |
| 明确的流程状态推进 | 同一 Collection 的 Kanban，按状态分组；技术类别不自动变成工作流 |
| 同一批记录需要多种观察方式 | 给同一 Collection 增加视图，不创建三份数据 |
| 来源原件或交付模板 | 文件附件；正文保留可检索知识及来源链接，附件样式不代替内容整理 |
| 现象、布局、对照证据 | 图片＋就近图注；多图先整体后细节 |
| 命令、代码、报文 / 数学关系 | 代码块 / TeX；无此类内容不为装饰插入 |
| 确定的流程、关系 / 探索性自由布局 | Mermaid / 可编辑白板，依相应技能和能力核验实现 |

分隔线只用于内容组之间：`extraLight`（稀疏点）适合轻转折，`light`（密点）适合相关组分界，`regular`（细实线）适合明确章节边界，`strong`（粗实线）仅用于较强分区。标题和留白足够时不用线。`pageBreak` 用于明确要求的版面分隔；不是子页面，也不保证所有导出格式有同样分页效果，导出用途需要另验。Washi 是页面主题的分隔装饰，不等同这些原生线枚举。

### 合集字段、记录正文与独立知识页

先区分对象，再判断读者需要理解什么、完成什么判断或操作：

- 合集记录页面：每一行／条目天然是页面，有自己的 ID，标题字段中的每个值是对应记录的入口；正文可空。新增记录即新增记录页面，补写或移除正文不改变记录页面是否存在，不以纸张图标判断。
- 属性列：区域、分类、状态等字段，不是独立页面；新增属性列不会新增记录页面。块链接或关系单元格指向已有目标，不复制目标页面。
- 独立知识页：承载可单独阅读的方法、规范、概念等主题，可位于目录或父页之下；只有主题有独立用途且现有页面不适合承载时才另建。它与合集记录页面的区别是内容职责，不是能否打开或被引用。

因此要决定的是是否填写记录正文、是否另建独立知识页；记录本身可打开不构成补正文或另建子页的理由。多视图共享同批记录，定位使用实际记录 ID，不用随筛选排序变化的显示行号。纸张图标、字数及链接数量不是内容门槛。

创建这三类对象前按[共用流程的语义查重规则](content-workflow.md#创建前的语义查重与复用)检查别名和同义内容；同一字段或记录优先复用，已有知识页优先链接。不同项目实例可共享方法，不因此合并为一条记录。

| 内容用途 | 优先承载方式 |
| --- | --- |
| 识别、筛选、比较记录 | 字段；名称、分类、条件、状态等直接表达 |
| 解释某条关联的用途与边界 | 可读链接标签、简短说明属性或共用导读；不自动生成正文 |
| 理解或处理该条自身的证据、分析、决策、操作或验证过程 | 记录正文；例如案例的现象与整改、评审问题的依据和闭环、试验的过程与结果 |
| 学习可供多条记录复用的实质方法或专题 | 复用已有知识页；有独立阅读任务且无合适承载页时再新建并链接 |

短决策及其理由也可能需要正文，无需凑齐图片、章节或步骤；长篇重复出处或复制资料也不因此值得建页。关键分类条件在列表或导读保留摘要，正文解释依据。相同内容只维护一处，优先链接；不得为消除图标而删掉有用证据或记录过程，也不得把所有合集限制为字段清单。

### 合集中的知识关联与出处

- 主要字段用于识别对象；需要打开已有知识时增加块链接字段，如“相关知识”。已有实质页面优先复用，不为每个分类名称创建空页，也不为了双链复制正文。
- 是否检索与同批结果复用按[共用内容流程](content-workflow.md#关联检索按需触发同批复用)判断，不为每个记录页面强制搜索或加链接。实际建链须解释“为什么相关、用于什么”，读取目标相关正文或属性及必要上下文。原始依据、校核方法、经验案例分别保留身份；相似名称不是适用性证据。没有可靠匹配就留空，并在合集导读说明空白不代表没有要求。
- 主要链接放块链接字段；补充资料按实际用途选择补充链接属性、已有知识页或确有阅读任务的记录正文，不因多个链接自动补正文，也不为少量资料预建大量空字段。目标有项目或条件边界时，就近保留可读说明；影响分类或采用结论的条件在列表或导读能识别，不能只藏在详情或目标页。
- 共用原件和模板放合集所在页；行号、原表分类和完整摘录用独立来源字段，默认按阅读需要隐藏，提供“来源核对”视图。不要在标题或每个单元格后重复长出处。
- 需要两个合集互相维护结构化关系时才用关系字段。普通内部链接的反向引用用于导航，不意味着两份正文同步、证据有效或适用范围相同。可见链接要有可读名称，不能把块 ID 当最终标签；实现与验收见[共用块格式](craft-blocks.md#知识链接与反向引用)。

## 按材料选择结构

下面是可调整的组织顺序，不是必填模板。缺少某类内容就省略，不虚构材料来填章节。

### 短追加
沿用相邻正文、标题、列表和颜色。必要时增加一个提示或结论块；不新建卡片网格、目录或整套配色。只有开始独立的大节才考虑分隔。

### 概念与参考知识
核心解释 → 如何理解/使用 → 对比、关系或例子 → 必要边界与来源。重复属性适合小表，关系复杂时选一张小图；项目实例与通用原理标清范围，不把标准条款、阈值和经验混写。

### 学习笔记
学习目标 → 材料如何读 → 关键概念/字段 → 有帮助的实例 → 可复用检查方法。材料名、版本、项目和日期紧凑呈现；公司缩写等局部疑点就近标注。长推导或次要样例可折叠，原附件标明规范、历史资料或示例用途。

### 问题案例
当前判断及状态 → 现象与条件 → 现场图和图注 → 已证实/疑似机制 → 整改和验证。按实际情况补充后果、风险条件与核验清单；根因整改和辅助防护分清，未证实根因明确保留疑似身份，不自动生成放行结论。

### 流程与检查清单
目的与进入条件 → 有序步骤或流程图 → 输入输出/验收条件 → 常见问题。必做步骤不能藏进折叠；只有读者需要执行的条目才用任务块，不把参考原则全部变成待办。

### 索引与知识入口
简短导读 → 有意义的主题入口 → 相关资料。主入口可用 regular/large 卡片，同级分类可用 small/square；卡片打开后须有内容，已有页面优先链接，避免再建内容副本。持续管理的重复记录适合 Collection。

## 图表、媒体与层级

- Mermaid 用于文字关系能清楚表达的小图。优先当前 Craft 支持的流程/时序/状态等类型；不要假定完整 Mermaid 语法都能渲染。Mindmap、Gantt 等是否支持须先核实，不能照搬其他渲染器的成功结果。
- 原生白板确有助于理解时，可纳入本次方案；在同一任务读取已安装的 [craft-page-visualizer](../../craft-page-visualizer/SKILL.md) 执行可编辑白板部分，保留当前归档授权和空间边界，不自行启动其他代理。该 skill 不可用时说明限制，选可用的图表表达；不以图片冒充可编辑白板。
- 图和公式后保留简短文字解释。不能靠图的布局、箭头或颜色暗示来源没有支持的因果关系。
- 图片紧跟相关内容，多图按整体到细节排序；图注说明必要的视角、标记、状态、日期与来源。不能让来源说明与图分离。
- 附件原结构有价值时保留原文件；正文提炼方法，不把所有工作表逐行搬进笔记。链接和附件用描述性名称。
- 卡片是带样式的子页面，不是通用段落容器。父页在卡片纵向堆叠后仍能理解，主要说明放在卡片之前。

## 页面级样式与移动阅读

已有页面默认保留主题、封面、背景与字体。新页、知识入口或用户要求视觉设计时，可以有目的地选统一字体、克制的卡片背景或相关封面；重要页面级变化纳入已有预览或直接写入授权范围，不为常规块级排版增加逐项确认。

使用已支持且可验证的样式；没有能力依据时不猜主题 ID、封面字段或装饰参数。主题可能同时覆盖多种页面属性，应先看现状。普通知识页不为装饰自动搜索 Unsplash；有明确视觉用途时可选相关图片并保留来源，不能代替现场图或工程证据。

移动端保持纵向阅读顺序：不要仅靠并排表达对比或步骤，宽表改为拆表或键值小节，公式/图表过宽时拆解，长代码不要承载必读正文。关键结论、条件、风险留在折叠外；图注与图片相邻。结构检查不能冒充真机视觉测试。

## 预览与验收

预览只解释重要选择：选哪种内容结构、为何需要卡片/折叠/图表/公式、来源附件如何放、是否调整页面样式。无需枚举每次加粗或每个标题。

写后按 [共用写入协议](write-protocol.md) 校验：
- 正文连贯，重点可扫描；新增内容融入正确承载页，未重复页面标题或旧知识。
- 每份新增记录正文或独立子页都有具体阅读用途；仅链接备注优先留在属性，案例与过程不被强行压成字段。非空正文和链接通过验证，不能代替这项必要性判断。
- 标题、焦点/强调、折叠、卡片等实际成为预期原生结构；卡片有子内容，折叠包含预期条目。
- 必要结论和边界可见；表格宽度合理，颜色与文字含义一致，图片、图注与附件顺序正确。
- Mermaid/公式保留可编辑源及预期块类型；可用时打开页面查看实际渲染，检查错误、截断和顺序。
- 回读只能验证结构属性时，明确说明视觉尚未验证；不把“代码已保存”说成“图已正确显示”。格式未达到方案时先修复同一批块，避免重复创建。
