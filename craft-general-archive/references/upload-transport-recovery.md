# Craft 图片上传的连接恢复

仅用于 HTTP 上传出现 `ProxyError`、`RemoteDisconnected` 或响应丢失的情况。沿用当前任务的空间、凭据与写入授权，不把网络恢复变成新的内容审批。

## 先区分错误

- `RemoteDisconnected` 只说明尚未收到有效 HTTP 响应时连接被关闭，单凭此错误不能认定代理故障、凭据失效或文件过大。
- `ProxyError` 表明代理连接环节失败；小请求或 `GET /connection` 成功，不代表图片上传能通过同一代理。
- 保存脱敏后的异常类型、HTTP 状态（如有）、文件字节数和耗时；不要输出含凭据的 URL、代理凭据或完整原始异常字符串。
- 401/403 等明确权限拒绝不适用直连恢复。413 等大小限制按服务端响应处理，不能通过切换网络规避。不要仅因连接关闭就缩图、转有损格式或改 MIME。

## 有条件地恢复上传

1. 先回读目标页，按插入锚点、来源及媒体块核对落盘情况。已存在则验证并复用；状态不明时停止上传，不重发。
2. 检查当前请求是否继承环境或本机代理，仅记录必要的脱敏信息。出现代理错误时，如该代理不是组织强制通道、任务没有要求必须使用它，可在本次请求专用会话中测试直连；不修改系统代理、全局环境变量或其他任务的配置。
3. 使用相同授权 API 地址，先直连 `GET /connection` 并确认目标空间。保持 TLS 证书验证；如原连接依赖自定义 CA 或认证配置，应显式保留，不以关闭验证解决问题。
4. 直连读取成功且已确认目标图片未落盘时，对该图片执行一次直连补传。这个有新诊断依据的连接切换，不等于在同一失败连接上重复重试。上传使用原接口契约、实际 MIME 和二进制文件内容；不重新创建正文或页面。
5. 补传后回读图片块与相邻图注，确认数量、顺序和来源。若补传失败或状态仍不明，停止该图片及依赖操作，保留成功内容和本地原件，准确记录未完成部分。后续图片分别去重、上传并验证，避免整批重跑。
6. 成功后更新之前的“待补传”说明。报告已证实的故障环节与恢复结果，不把一次成功推断成所有上传都应直连。

Python `requests` 的请求级示例（地址与凭据仍由当前技能的连接规则提供）：

```python
session = requests.Session()
session.trust_env = False  # 仅本会话；不继承环境代理、netrc 等隐式配置
session.headers.update({"User-Agent": "CraftArchive/1.0", "Accept": "application/json"})
# TLS 验证保持开启；需要的自定义 CA/认证须显式配置。
# 先确认 /connection 的空间，再上传；用 with open(path, "rb") 发送文件。
```

已验证案例（2026-09-27，Car）：两张无损压缩 PNG 经本机代理上传时先报 `RemoteDisconnected`，换客户端诊断为 `ProxyError`；同一 API 直连读取成功，随后两张上传均返回 HTTP 200，回读确认 image 块及图文顺序。证据支持该次代理路径存在问题，未证明代理内部断开的具体原因。
