# 滴答执行流程

语义和默认值统一见 [决策规则](task-conversion.md)。这里负责落实位置、去重、写入和恢复。

| 阶段 | 动作 | 通过依据 |
| --- | --- | --- |
| 发现 | 读取工具 schema、账户和范围；按需读清单、标签、分栏 | 当前真实 ID 和读取结果 |
| 定位 | 笔记按默认值；行动按用户指定、已有绑定、交付项目、已有功能清单选择 | 范围内、未关闭；明确只读清单排除 |
| 去重 | 来源 URL／稳定 ID／附件哈希查记录及候选 | 同一来源及行动身份，不只同名 |
| 准备 | 准备任务字段，附件预检，运行参数校验 | 参数通过，未知能力与权限保持未知 |
| 写入 | 创建后记录 ID；父任务先于子任务，原附件关联同一任务 | 可追溯的逐项结果 |
| 回读 | 对照类型、位置、正文、步骤、日期、标签和附件 | 全部必需结果真实存在才 `executed` |

工具短名索引：`list_projects/list_project_groups/list_tags/list_columns/search_task/get_task_in_project/create_task/update_task`。实际调用以实时 schema 为准。检查 `isError` 和业务错误，再解析 `structuredContent` 或 `result`；错误不是空列表。

`permission=null` 是未显式返回权限，结合范围与实际响应处理。分组与智能视图不是任务清单。分栏需属于当前清单。行动清单用途不明时只读取少量相关任务判断。

## 收集箱解析

1. 读当前账户完整清单；若契约规定未分页结果才包含虚拟收集箱，按该方式再读一次。
2. 仍未返回时，从同账户、已明确显示在收集箱内的任务或客户端收集箱入口取候选 `projectId`，再核验归属。任意无分类任务不能作为证据，不硬编码 ID。
3. 若正式契约明确保证省略 `projectId` 会写入当前账户收集箱，宿主可采用该默认行为，但校验前仍须解析可核验目的地，写后确认实际 ID。参数可选不等于默认行为已知。
4. 仍无法核验时返回 `needs_connection`／位置缺口并保留方案；不试写探测，也不静默改存其他清单。

## 去重与恢复身份

来源 URL 写入正文并作搜索键。保留原始 URL；规范化键只去已知追踪参数，不删除可能改变资料身份的 query 或片段。无 URL 时，用附件 SHA-256 或规范化全文 SHA-256 查操作记录，再读远端确认。

普通对话可在工作目录或任务临时目录保存最小记录：操作 ID、来源键、账户／清单、行动身份、任务 ID、附件 ID／哈希和阶段状态。凭据与额外全文副本不进入记录。全文哈希只标识素材版本；多项行动分别追踪，内容变化不自动新建整份。

无绑定时搜索原标题或辨识度高的正文片段，读候选比较内容。搜索失败不能宣称无重复。同名不同内容不合并；已知模糊重复无法判定时澄清该项。跨会话缺记录且搜索不完整时说明去重覆盖范围。

## 回读失败

| 发现 | 恢复动作 |
| --- | --- |
| NOTE 被回读为 TEXT | 保留原 ID，读最新任务；接口支持转换时仅修正 `kind=NOTE` 并保留内容、位置和附件，再读一次。仍不符／不支持则 `partial`，说明类型未落实，不另建副本 |
| 属性被忽略或改写 | 对照最新值和 schema，最多一次有依据的局部修正；仍不符则报告具体缺口 |
| 超时／响应丢失 | 按原操作记录核对后置状态；证实未执行才重试一次，否则 `unknown` |
| 正文成功，附件失败 | `partial`，只补缺失附件；图片是唯一内容时按附件流程报告空记录状态 |
| 用户编辑冲突 | 停止冲突字段更新，保留最新用户数据 |

检查项／子任务是否推进主任务完成，以实际接口和回读为准，不视为固定联动。创建采用未完成状态；资料检查项不充当整个项目的完成条件。

交付核验后的位置、链接、附件结果与材料日期提示。内部操作记录和错误细节留在执行记录中。
