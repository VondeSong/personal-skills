# 私有附件流程（仅有附件时读取）

采用已授权、能使用同账户会话的执行适配器。任务 MCP 可写不代表附件可上传；凭据由宿主／浏览器保管，模型只接收可用状态和结果。独立的资料默认值见 [决策规则](task-conversion.md)。

## 开关与创建前预检

每次带附件都先预检，尤其图片／文件是唯一有效内容时。自动生成的图片描述不算“独立正文”，不能据此绕过预检。

适配器输入 `attachment_mode=enabled|disabled`。无保存设置时采用 enabled，并向预检脚本显式传入；这只表示允许在本次已授权保存范围内使用通道。disabled 停止附件操作。

`scripts/attachment_preflight.py manifest.json` 检查本地原件、大小、剩余额度证据和通道状态，计算 SHA-256。它是离线闸门；会话、账号匹配、协议和额度证据由正式适配器提供，不会自行读取 Cookie 或联网探测。

最小输入如下；示例状态仅示意，调用时替换为实际证据。`independent_content` 只表示有用户原始独立正文。状态须来自本次新鲜探测，不能把上次成功当成本次证据。

```json
{
  "attachment_mode": "enabled", "session": "ready", "account_match": true,
  "protocol": "verified", "independent_content": false,
  "limits": {"account_max_bytes": null, "adapter_max_bytes": null,
             "remaining_task_slots": null, "remaining_daily_slots": null},
  "attachments": [{"path": "/actual/local/original.png"}]
}
```

输出 `ready/body_only/blocked`，分别表示可上传、仅可保存独立正文、先不创建。仅 ready 的退出码为 0；其他结果不得当作附件成功。实际上传前复核原件未变化，变化后重新预检。

| 项目 | 处理 |
| --- | --- |
| 原件 | 实际可读文件、原名、大小、MIME／可解析内容；以文件字节计算哈希 |
| 会话与账户 | `session=ready`、`account_match=true` 才执行；缺失、过期、不匹配或未知分别报告 |
| 大小 | 账户上限未验证时，本技能按 **10 MB = 10,000,000 字节** 保守处理；这是技能边界，不宣称平台官方精确限额。已验证上限与适配器上限取更小值 |
| 数量与余额 | 有可靠剩余数则检查；未知明确标注。预检通过也不保证实际上传时仍有额度 |
| 协议 | 用下述只读探测验证；协议变化暂停本次附件通道，不进行盲目重试 |

预检已知失败且附件是唯一内容时，保留本地素材与待写方案，**先不创建空笔记**。有用户提供的独立正文时可保存正文并报告附件未保存。预检后上传仍可能失败：保留原任务 ID 为 partial，明确说明唯一附件未完成，恢复时复用该记录；不重复新建，也不把生成描述当作原图归档成功。

## 轻量健康探测

1. 检查当前授权适配器提供的非敏感会话状态、同账户证据和能力版本。
2. 有已知且获准读取的附件时，认证回读该资源或其元数据；核验状态、响应类型和可解析内容。没有已知附件时可用同账户正式会话检查与元数据读取；不伪造附件 ID 试错。
3. 将结果记为 `protocol=verified/changed/unknown`。HTML 登录页、接口路径改变或无法解释的返回视为 changed/unknown，停止附件通道，按是否有独立正文降级。
4. 上传测试文件的写入探测只用于明确请求的联调，并需指定测试目标；普通健康检查不产生新记录。本次真实附件上传后的回读就是最终端到端检查。

## 已观察到的私有协议

以下为适配器维护资料，不是长期接口承诺。使用前确认当前适配器仍兼容。

| 操作 | 协议 |
| --- | --- |
| 上传 | `POST https://api.dida365.com/api/v1/attachment/upload/{projectId}/{taskId}/{attachmentId}`，受控 Cookie，multipart `file`，真实原名和 MIME |
| 正文引用 | `<attachmentId>/<URL 编码的原文件名>`，图片用对应 Markdown；TEXT/NOTE 写 content，CHECKLIST 写 desc |
| 认证回读 | `GET https://api.dida365.com/api/v1/attachment/{projectId}/{taskId}/{attachmentId}.{extension}`，无有效扩展名时只用 ID |
| 元数据 | 已授权适配器可读 `GET https://api.dida365.com/api/v3/batch/check/0`，只取本次任务所需结果 |

正文引用不是下载 URL。附件 ID 由宿主／官方客户端生成并保存，常见实现为 12 字节随机值的 24 位十六进制。去重键绑定账户、清单、任务及 SHA-256；结果未知时保留原 ID，不换 ID 重传。

官方客户端可能将 CHECKLIST 附件存入原生附件列表，不出现在 desc 或普通 MCP 返回中。任务刷新后仍显示同 ID 的附件，且认证原件回读通过，即可证明有效关联；不为制造 Markdown 引用而重复上传或重写正文。

官方网页已登录且当前工具支持文件选择器时，可通过其原生“上传附件”控件使用同账户私有上传流程。用实际任务链接核验账户访问；让网页自行保管会话并生成 ID，随后经任务回读取得引用。此路径不读取或导出 Cookie。没有可调用桥接、也没有可用网页上传能力时，报告能力缺失。

## 上传、回读与恢复

创建／复用任务 → 登记原件身份 → 上传或复用该任务中的同哈希附件 → 写入真实引用 → 回读同一任务 → 认证取得附件并核验内容。可下载原件时比较字节数和 SHA-256；否则明确核验达到的层级。

分别记录 uploaded、linked、readable，三者都通过才算附件完成。HTTP 200 或缩略图存在不能独自证明原件完整；读取到 HTML 时核验是否原文件本身就是 HTML，而不是登录页。

401/403 检查会话、权限与账户；429 按服务提示延期；超限／额度不足停止后续上传。协议变化立即关闭本次通道。先回读未知请求的结果，证实未执行才重试一次；仍未知返回 unknown。保持原件，压缩、丢弃或换共享链接需用户明确选择。
