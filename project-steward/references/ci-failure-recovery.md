# 失败复现与验证收敛

本方法由 `ci-execution-governance.md` 在已有失败、重复昂贵实验或准备重验时加载；沿用其验证计划、权限和预算，不为普通小改动增加流程。

## 1. 保留失败并界定重验

第一次失败保留候选提交、计划身份、runner、作业、步骤、测试节点、环境准备、缓存状态、日志和产物。状态页与 watcher 只是可能截断名称的展示投影；失败身份必须从机器可读接口还原准确 SHA、run、attempt、job、check、日志和产物。先把失败归入工作流编排、基础设施或外部环境、测试驱动或夹具、正式产品链、最终断言中的最早一层，再决定修复与重跑。

只有存在真实瞬态依据时，允许在相同提交、输入、runner 和命令下做一次原样重跑。重跑范围限于失败作业及依赖其结果的质量门；已经成功、证据仍新鲜且不依赖失败产物的作业不重新运行完整工作流。一次原样重跑再次失败，或者第一次已经提供确定性证据时，停止重跑并修复最早错误边界。不能用通用 retry、提高次数或延长所有超时把稳定缺陷变成绿色概率。

修复后先重跑原失败检查、修复触及的消费者和对应质量门。只有修复改变公共合同、全局配置、测试收集、共享夹具、执行环境或其它作业的正式输入，才扩大到受影响作业；只有项目规则或用户承诺要求时才重新运行完整工作流。较早成功证据与修复后结果可以共同使用的前提，是修复没有触及它们的生产者、输入、环境或消费者。

早期冒烟暴露真实产品或冷启动缺陷时，修复产品或测试边界并重新走同一冷链；不能把失败归咎于“冒烟太早”后移除它。如果相同失败在本地或 CI 稳定复现，就不再消耗一次瞬态重跑。

## 2. 先用已有证据消除确定性失败

保存的请求、工具回执、事件或持久快照足以触发问题时，先从隔离副本经过正式解析、存储、评分或消费入口离线复现。保留原始失败与评分，不把手工校正的副本或 mock 核心链所得结果记为真实模型通过。数据不足以复现时，只补能区分当前假设的最小诊断证据；不为遵守顺序伪造离线结论。

把同一根因及已确认的直接消费者集中修复，先完成夹具语义、运行入口与失败传播预检，再运行最小相关回归和必要的一次统一构建。仅改诊断脚本或测试材料而不影响产品二进制时，不重建产品。成组修复能证明合并结果，但不能凭总耗时改善归因某一个补丁；单变量性能归因遵循 `project-performance-governance.md`。

真实模型、代表规模或完整原生验证只补离线检查不能证明的承诺。启动前在现有验证计划中说明未闭合问题、预期新增证据及最窄受影响范围；没有新的判别目标，不因更换候选名称自动启动下一批。批次结束先区分产品缺陷、测试驱动问题、环境问题、未知项和工程优化目标，再选择有证据支持的下一步。已授权的独立任务继续推进，不能把停止无效重跑解释为停止全部开发。

## 3. 复用实验时保留身份与统计含义

复用旧结果或让一次昂贵运行覆盖多项验收，须证明相关生产者和消费者未受影响，输入内容、权限、目标、初始状态、执行路径、环境、测量与评分合同等价。仅名称相同、样本相同或最终报告相似不够。提示词、工具 schema 或共享执行链变化时，沿消费者判断影响；无法界定则重验该范围。

在运行前声明共享关系，保留各项断言、原始运行身份、实际调用次数及样本关联；同一次运行不能算多个独立样本，也不能替代合同明确要求的独立重复。历史失败保留原判定，不从多批结果中挑选成功凑数。不新建平行台账，使用既有计划和结果记录。

## 4. 桌面只用于不可替代的原生证据

能由文件、日志、正式接口或离线回放证明的内容，优先后台完成。只有焦点、键盘、布局、原生呈现等必须经真实界面验证的缺口才控制桌面；操作前明确缺失断言，完成后释放桌面。构建、回归或模型等待期间不持续点击、截图或抢占用户输入；确需观测动态视觉行为时，只在对应采样区间操作。后台证据不能冒充原生通过，未受影响的有效原生证据也不重复采集。

本方法不增加审批步骤；沿用用户和项目已授予的执行与预算权限，不能把本次项目的自主授权推广为其它项目的授权。
