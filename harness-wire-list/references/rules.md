# 工程规则与输出映射

按真实模板顺序指定每列；不可取得的列 `field: null`，不猜值。
```json
{"columns":[
 {"header":"Wire","field":"wire_id"},
 {"header":"自 部件: 名称","field":"from_id"},
 {"header":"自 端口/引脚/孔位: 名称","field":"from_pin"},
 {"header":"到 部件: 名称","field":"to_id"},
 {"header":"到 端口/引脚/孔位: 名称","field":"to_pin"},
 {"header":"线束","field":"harness"},
 {"header":"LengthMm","field":"length"}
]}
```
可用字段是提取列加 `source_id,harness,record_id`。标识符与原始记录按文本保存；主表中可无损转换的截面积、长度为数值，单位在来源页保留。空白真正留空，`-` 原样保留。以 `=,+,-,@` 开头的源文本也不能变成公式。

T29 常见对应：Wire→wire_id、Multicore→multicore、导线截面积→size、导线颜色→color、导线材料→material、自/到部件→from_id/to_id、配合设备名称→from_name/to_name、孔位→from_pin/to_pin、端子→terminal1/2、雨塞→seal1/2、选项表达式→option、线束→harness、LengthMm→length（仅 mm）。实际映射须读本次模板，不预设一定为29列。

器件名/塑壳料号补充：按源图/版本/线束/接口代号精确关联，记录新增字段自己的单元格证据。已有名称冲突时保留双方，不覆盖。核对料号后缀、产品号与塑壳号、防错编码、配置，未知字段继续空白。

- 相同 Wire ID 可能是不同线束、配置或端点，不能只按线号去重。
- 接点表可核导通，分支、双绞对、屏蔽和排流线不因此合并。
- INLINE 两侧名称可能顺序相反，对接要核孔位、信号及接口定义，不能靠名称互换自动短接。两侧线长不合成原图字段。
- From/To 不自动等于信号发送/接收；物理连接不证明主从、交换机转发或车辆功能。
- 导线表、针脚表、成品线表及数模冲突没有默认胜出者。仅在用户确认或版本/更改单证据明确时修正，并保留原值及理由。
- 完整性范围先于功能筛选，不能仅搜 Camera/Radar 就宣称全量 wire list。

报告源图/线束/表数、预期与实际记录、重复组、端点覆盖、歧义、不可比较字段、差异及未覆盖区域。数据问题未解决时主表仍可交付，但明确待复核。不要为好看的通过率隐去未知项。

对外文件保留必要工程来源、版本与不确定性，不放内部提示词、运行路径或执行过程。原始证据和技术冲突不能为了外观整洁删除。
