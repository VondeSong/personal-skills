# Eagle 资源库整理

让用户以后能按项目或主题、用途、内容特征快速找回素材。以当前 Eagle 库的实际内容为准；[Car 库案例](references/car-case.md)仅在当前库是 Car 或需要相似案例时阅读，不能当作其他库的固定模板。

## 明确对象与任务边界

- 先通过 Eagle MCP 获取应用信息，优先记录**当前库绝对路径**，同时记录可用的库名或标识；不要仅凭可能重名的库名判断库身份。开始分析、结束分析和任何写入前都重新确认，防止用户中途切库。路径或唯一标识无法核实时，明确说明身份只能暂定；不要执行跨库风险的写入。MCP只针对当前库时，不声称已检查其他库。
- 用户要求“分析、规划、建议、先不要修改”时保持只读。读取库和原文件不构成改动授权。用户明确要求实施整理时，按其授权范围执行；不因本 skill 自行扩大到删除、覆盖原文件或其他库。
- Eagle MCP 无法连接时说明限制。不要把过往 Car 库快照或本地某个目录冒充当前库。

## 从全量盘点到足够了解

1. 读取全部文件夹层级、现有标签与标签组、文件数量，以及尽可能完整的文件元数据。按 Eagle **唯一文件 ID** 计数；同一 ID 可以同时属于几个文件夹，目录关联数不能相加为文件总数。记录未分类、未打标签、扩展名分布，以及最大或命名不清的目录。
2. 分层选择抽样：尽量给每个非空目录至少一个样本；目录特别多时，按层级、规模与命名聚类抽取，并列出未覆盖的位置。覆盖图片、视频、PDF、Office及其他实际存在的格式；对最大混合目录中的不同内容簇，以及项目、来源、年份或稀有格式追加样本。用户若设上限须遵守；若允许按了解程度决定，就不要预设60个或其他固定停止数。
3. 对每个样本记录可核实的证据及其边界。图片看画面，视频在不同时间点看画面且必要时听音频，文档看封面与相关正文，表格检查实际数据而非只看模板标题，特殊格式至少核对元数据或文件头。仅看文件名、缩略图、开头页面或视频抽帧时，明确写出限制；不能把“抽看”写成“全文理解”。
4. 当全量元数据已盘点，主要目录/格式/项目/来源及最大混合目录的不同内容簇都有代表样本，再挑最可能推翻现有方案的未覆盖簇进行一轮补样；若没有产生新的一级类别、关键项目边界或标签规则，可以停止。报告未抽查数量、未覆盖位置和仍需核对的类别；不把样本结论机械套用至全库。

## 判断文件夹与标签

- 沿用有效的现有项目和来源分类，优先按项目或可复用目的确定**主归属**；再用标签表达跨目录主题和用途。将“图片、视频、文件、ScreenRecorder、other”等混合入口逐项分流，不能整夹按一个项目或主题处理。文件夹通常控制在2～3层，只为实际有内容的类别建层；日期和格式通常留给文件名、元数据和筛选器。
- 区分项目专用文件与通用方法/模板、供应商目录、课程、个人资料。已经填写的项目校核记录不是空白通用模板；课程的弹幕和字幕跟随课程，不按扩展名拆散。项目身份不明的工程资料可以暂留来源或“项目待核对”，不能猜项目号。
- 标签使用简体中文，以**项目、专业主题、用途、来源、整理状态**为主要维度；正式项目代号、品牌和技术缩写保持原写法。选择少量可复用、能改善检索的词，统一同义词并保留确有区别的术语。不要把文件名每个词、日期、精确零件号或文件扩展名都建成标签；不要凭文件名推断“最新版、已批准、问题已解决”。当前没有标签时，规划的是新词表，不要声称已合并旧标签。
- 同一文件可有多个文件夹关联。报告中的**主归属只是推荐的主要检索位置**，不是声称 Eagle 存在独立的“主文件夹”字段；另有辅助关联时列出。重复目录入口不等于重复文件；同名、相似画面或同主题不同格式也不等于可以删除的重复文件。

## XV 视频审核标签规则

- 整理 XV 库的视频时，Eagle 标签用于有证据支持的中性属性及内容审核所需的非露骨行为分类。中性属性包括可见人数、场景、画面元素、横竖屏、露脸情况、机位和拍摄特点；作品与制作资料需要可靠来源。
- 审核状态和风险发现不写入 Eagle 标签，不使用“审核：”“审核发现：”前缀。性行为分类可以保留，但不加“审核行为：”前缀，例如“手部性接触”“口腔与生殖器接触”；尚未确认的判断保留“疑似”，例如“疑似性交”，不能写成已确认。没有证据的行为不写标签，不从用户词表自动生成事实。
- 每个行为标签须在备注、视频时间批注或长期审核档案中关联证据时间点、非露骨依据、可靠性和检查范围。标签是片段层面的分类，不代表全片持续发生；审核状态、规则匹配和最终决定保存在审核记录中。
- 仅修改标签呈现时复用已有证据，不因标签规则变化重新抽帧或删除审核记录；同步更新当前档案的拟写入标签及展示规则，避免以后复用档案时重新加回。
- 清理已有标签按用户授权的素材范围执行。针对选中视频的修改不扩展为全库清理；保留其他标签、文件夹关联及原始素材，保存改动前后记录并读回核验。

## 交付与实施

分析结果应包含：当前库与盘点数字、抽样范围及停止理由、建议目录树和各类用途、简体中文标签规则及同义词表、**逐个抽样文件**的“文件名或ID → 当前文件夹 → 建议文件夹 → 标签 → 判断依据 → 待核对状态”，以及现有结构需要调整的具体位置。表格较大时提供可筛选文件，并在回答里点出关键发现。涉及旧格式、无音频转写、黑屏或版本冲突的项目，把不确定性放在对应行，不靠泛泛声明掩盖。

若用户明确要求执行整理，先确认当前库仍与分析对象一致，用文件 ID 复核目标及原有文件夹/标签，保存可回退的改动记录。先处理依据充分的一小批，核查标签、主归属和检索效果后再分批继续；有项目或内容歧义的文件保持待核对。添加新归属与移除旧归属是不同操作，按用户的实际整理目标处理，避免因多个目录入口误删源文件。实施后复查计数与样本，并准确报告已改动的范围及仍未处理的文件。
