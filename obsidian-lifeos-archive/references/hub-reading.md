# Sources 与 Hub 阅读

Sources 的 `X/`、`Telegram/` 及其子目录保存原始素材。支持本地素材接入的 Hub 桌面版，在默认保存库设为 Sources 时，可通过“阅读 → 同步与连接 → 设置 → 保存位置与同步频率”检查原件。新版默认仅手动，保存后可点“立即检查本地素材”；也可设置独立的本地检查间隔（5–1440 分钟，0 表示仅手动）。定时检查只在 Hub 运行时执行；重启保留设置，按上次检查时间判断是否到期。联网收件使用另一项频率，不与本地检查混用。无需 Obsidian MCP。实际能力、频率与保存位置要从运行版本和设置核实，不能只凭本说明认为旧程序已升级。

把 Sources 加入 Hub 资料库用于主界面全文搜索；接入 X、Telegram 阅读用于阅读进度、标签与阅读筛选。两条入口可以同时存在，引用同一份 Obsidian 原件，不因此另建原件副本。Hub 内仍有搜索快照、索引及阅读缓存，搜索附件也可能有内容缓存；不能表述为数据库完全不复制内容。加入资料库不等于加入阅读，阅读接入也不等于登记整个搜索资料库。不要为避免两个入口而删除原件或阅读状态。

- 保存前仍按来源身份、正文、回复和附件检查重复；保留真实来源 URL/ID、作者、原始日期及转发上下文。频道主页不能充当消息 ID；不为接入 Hub 补造外部字段、强制模板或改写原件。
- X 原件落在 `X/` 的实际同类目录，Telegram 原件落在 `Telegram/` 的实际同类目录；本地附件保持实际可解析引用。正文内的平台作者标签不自动变成用户分类。
- Hub 按推文/消息身份或正文与附件内容去重；已有阅读正文和状态优先。同来源不同版本保留在 Sources，不为增加阅读卡片而仿造 ID。首次新建后，已读、进行中、放弃、归档、标签和删除状态由 Hub 当前记录负责，不能从原件的旧状态覆盖。
- 原件与附件只读接入，不反向改名、修改页面属性或触发平台取消收藏；缺失附件可晚到再接入。删除 Sources 原件不自动删除阅读缓存。其他来源和待归类目录不在这条自动接入范围内。
- 写后先核验原件、来源和附件。具备已授权的 Hub 查询能力时，再按来源身份或文件回执检查阅读条目、附件和状态；无需为正常归档直接写数据库。只能确认文件保存时，按实际设置报告“已保存，可在 Hub 检查本地素材”或“已保存，等待 Hub 按设定间隔接入”，不能宣称阅读列表已经显示。仅手动模式不承诺自动出现；用户已要求归档并接入阅读时，有受支持的 Hub 操作能力可立即检查，无需重复确认。
- 不显示时依次核实运行版本、默认保存库、原件是否在 X/Telegram 目录、本地检查频率与最近结果，以及当前阅读筛选；仅手动模式先用“立即检查本地素材”。先查回执和重复记录，不直接重复导入。调整 Hub 保存位置、迁移旧回执、批量补导或删除记录需要对应请求授权。
