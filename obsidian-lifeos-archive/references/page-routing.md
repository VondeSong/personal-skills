# OS 软件、AI 扩展与影视专项约定

仅在处理软件信息、软件使用知识、AI 扩展条目或影视条目时读取。用户原有专题约定确认于 2026-10-12；软件主页与 Buffer 子页约定确认于 2026-10-18，AI 扩展库分流确认于 2026-10-20。授权与全库边界见目标库 `AGENTS.md`，通用页面职责与归档判断见 `SKILL.md`，正文整理见按需参考；本文件维护专题特有约定。

## 软件主要位置

| 信息用途 | 主要维护位置 |
|---|---|
| 现行属性、短配置、使用技巧、插件与主题入口、界面及相关开发管理 | `Resources/效率提升/软件库/<软件名>.md`，作为软件唯一主入口 |
| 确需独立属性、生命周期或持续单独维护的详细专题、代码与排障资料 | `00_Inbox/Buffer/<软件名> - <具体问题>.md`，由主页引用并保留返回主页的链接 |
| 外部文章、平台消息或附件 | 按双库用途判断：明确收录的作者文章可在 OS；批量未整理与 X/Telegram 碎片先放 Sources。保留原文、出处和必要附件，不自动搬迁旧资料 |
| 普通独立项目、本人使用反思 | 仍分别按地图定位 Projects 与 Areas/数字自我；软件开发从软件主页串联实际工程与相关资料，不复制工程规范 |

软件对象实际目录为 `Resources/效率提升/软件库/`，已有浏览定义为 `Resources/效率提升/软件库.base`，筛选使用真实目录并排除 Buffer 子页。软件短内容先进入主页适合的小节，按主流程的独立维护信号再判断是否成篇，不因出现插件名就自动建文件。

Buffer 同时承载未决 OS 材料与长期软件子页。软件子页不因所在目录就被视为待处理，不要求日后迁出；所属软件通过主页与返回链接确定。共用专题只保留一份正文，可由多个主页引用；不预建空白子页或增加无用途字段。文件列表仍能展开 Buffer 查看文件，这不是隐藏插件方案。

2026-10-18 已落实 Obsidian 与 Hub。后续新增或用户明确整理的软件按此规则处理；其他软件和已有项目不自动迁移。先检索对象、文件名、别名和来源，避免另建同软件的并列入口。原 Notion 资料仅作历史来源；现行工程、构建和发布规则链接实际项目仓库中的适用文件，不在 OS 重复维护第二份。

## AI 扩展库：类型与接入方式

- MCP 工具、Agent Skill 及 AI 记忆与上下文系统的对象条目统一放在 `Resources/效率提升/AI扩展库/<名称>.md`，包括仅适用于某个客户端的扩展。与软件库独立；Codex、Claude Code 等客户端本体仍使用软件库主页，不将扩展条目作为某客户端的 Buffer 子页保存。
- 复用 `Resources/效率提升/AI扩展库.base`：全部视图按非空 `扩展类型` 纳入条目，按类型分组；“MCP 接入”按列表型 `接入方式` 是否含 MCP 筛选，“Skill”和“AI 记忆与上下文系统”按各自类型筛选。普通收录补充条目属性即可，不重建 Base 或覆盖用户调整的列宽、排序与布局。写后核对条目符合当前筛选；源码与静态筛选核验不等于已检查实际显示。
- `扩展类型` 描述对象本体，不限定为 MCP／Skill 两个值：Agent Skill 填 `Skill`，OpenViking、basic-memory 填 `AI 记忆与上下文系统`，其他对象根据已核实的核心定位选择类型。MCP 是接入协议，新增条目不能仅因提供 MCP 接口就以 MCP 代替本体类型；存量对象的重分类仍按本次授权范围处理。
- `接入方式` 独立使用列表，按官方材料填写 MCP、SDK、HTTP API、CLI 等已核实方式；不把这些协议或入口当作对象类别。`用途`、列表型 `适用客户端` 和 `来源` 按已核实信息填写；`来源` 使用官方仓库或原始地址，未知信息不猜。`阅读主题` 关联已存在的 `Areas/AI/AI - MOC` 及必要的实际任务主题；本人安装状态、版本、修改与实测结果只按实际记录补充。
- 先按名称、别名与来源判重，复用已有条目。同一扩展的公共说明保留一份，各客户端特有配置在条目中分小节记录；确需独立维护的长教程或排障资料由条目链接进入。这些专题不填写 `扩展类型`，避免在 Base 中被当作新的扩展条目，不套用软件 Buffer 子页落点。
- AI 扩展条目补充 `cover`，画廊沿用 `image: note.cover` 与 `imageFit: contain`。优先使用可直接访问的官方在线图片 URL；没有合适官方图片的自定义 Skill，可按用途选用来源和许可明确的通用在线图标，并在库说明中注明图标来源，不能冒充项目官方标识。使用在线图片前核验响应确为图片，不使用网页地址、需登录或临时签名的链接；在线来源不可用或明确需要离线保存时，库内图片放在 `99_Meta/assets/ai-extension-covers/`，`cover` 填实际路径。参考 [Obsidian Cards 的图片属性](https://obsidian.md/help/bases/views/cards)。普通收录复用“扩展画廊”和现有表格视图，不重建布局；URL 与源码核验不能替代 Obsidian 实际显示检查。
- Skill 笔记保存用途、触发条件、依赖与使用经验，实际运行文件由原仓库或安装目录维护；确需保留固定版本时，保留完整文件包与版本来源。

## 主页面的有效导航

主页和主题入口只保留已核实存在且有实际内容的导航目标；不把失效链接、空文件或迁移核验清单保留为“历史资料”展示。整理时需要保留的旧清单与原文放在库外可恢复备份中。未获清理授权时只报告问题，不自动删除旧内容；获授权删除目录时同步处理其直接入链，不为通过校验创建空白目标或重新建立已废弃目录。

OS 旧 `Resources/软件使用/软件资料/` 目录已于 2026-10-18 按用户要求撤销。软件信息在现行软件库主页重新维护，独立内容按 Buffer 约定处理；不从历史备份自动恢复旧目录或链接清单。

## 属性与维护

软件库由用户自行维护，仅按明确收录或修改请求操作；遵守根规则中的禁止管理报告约定。用户要求更新现行信息时，依据明确事实最小修改相关字段并保留来源与有效日期，不猜测本人使用状态、购买情况、费用或频率；来源快照、原始属性表与外部 ID 不改写成当前数据。

名称使用文件标题，属性沿用已有实用字段。不新增 Notion ID、迁移状态、源 JSON 路径等技术属性，不恢复用户已去掉的 `date:最后使用日期:is_datetime`、`关键快捷键`、`参考链接`、`软件名称` 或 `上次编辑时间`。必要出处和获取日期放在来源正文中。

## 画廊与附件

默认使用带图画廊，表格用于属性筛选。封面统一使用 `cover`，值为实际存在的库内图片普通路径，例如 `99_Meta/assets/software-covers/图片.png`，Base 使用 `image: note.cover`；不重复添加“封面”字段。图片优先用户素材或官方图标，缺图可用明确的通用封面。

核实图片引用及 Obsidian 实际识别情况。只有路径检查时，交付说明这一验证范围，不宣称画廊已正常显示。保留相关原资料、代码和附件，不为本次收录迁移或整理其他软件。

## 版本与影视条目

软件版本或平台差异较小时，在对应步骤或结论旁注明条件并追加；步骤或结论明显不同且需要独立使用时，按主流程判断新建专题并关联对象。一次故障、尝试或体验保留实际条件，不能写成所有版本的通用结论。

电影、电视剧与软件继续同库，沿用地图中的 `Resources/movie/`、`Resources/teleplay/`、`Resources/影视/` 等实际目录。作品条目可提供入口，但豆瓣等导入属性和同步正文受保护；简短观感只追加到明确适合且非同步管理的小节，完整影评或专题分析可独立成页并引用作品和来源。不得伪造 doubanId、评分、观看状态或其他未提供事实。
