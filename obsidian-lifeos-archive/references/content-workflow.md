# Obsidian 内容整理与阅读验收

用于新页、重大追加、混合主题、复杂来源、知识提炼及已授权的拆分与合并。定位、成篇判断、授权和通用写入步骤由 `SKILL.md` 维护；本参考负责正文组织、小节写法与重组后的引用核验，不依赖 Craft 技能或格式。

## 先明确读者需要

- 判断这条笔记要帮助读者理解概念、执行方法、回顾事件、追溯来源，还是保存原始资料。开头直接说明主题、用途或有依据的结论；短内容保持短，不为模板扩写。
- Sources 来源页保留原文及上下文，转录错误如需更正要明确标注。OS 专题按问题和主题组织，说明可使用的知识与依据；仅添加标签、排版或摘要不自动构成专题。专题页可去除口语赘述和重复，保留关键事实、术语、限制、单位与依据；不要将整理稿当成原文，也不把原件全文机械塞进专题。
- 个人记录保留本人提供的经历与判断，不补造情绪、动机或因果。项目记录保留具体条件和实际状态，疑似原因、已证实原因、尝试措施与验证结果各按材料记载。
- 混合材料按独立问题或用途判断是否分小节、分页面；共享上下文和原件可保留在来源页，再按需引用。不要为分类过度拆成零碎笔记。

## 将新增内容接入已有知识

- 沿用承载页的术语、标题层级和叙述方式，说明增量与旧知识的关系；不要每次追加都重写定义、背景和大段来源说明。
- 新小节必须延续页面目的。按主流程的“小节或独立文件（OS）”判断成篇，不因已有同关键词页面就强行追加，也不因能独立阅读就另建文件。
- 新写内容可以整理；已有原文只有在明确修改授权内才能融合或重写，否则在适合的锚点作自然衔接的增量。
- 正式知识正文不混入归档路径、候选评分、工具诊断或执行日志；这些留在任务反馈。Inbox 中尚待处理的材料可保留归属与疑点说明；长期软件子页不因位于 Buffer 就加上待处理标记。

## 阅读主题与页面属性（OS）

- 整页内容主题使用 `阅读主题` 列表，值为实际存在的主题页或 MOC 的双链；同一材料可以关联多个并列主题。它不限于 MOC，也不规定唯一父主题。新增归档不再同时添加同义的内容 tags。
- 主题页可以用简短范围说明、有依据的阅读整理和 Bases 自动资料视图起步，再逐步积累理解；MOC 保留阅读路线和必要人工导读，不重复维护全量材料清单。零散提及无需逐词分类，不为分类预先生成空页。
- `内容类型` 按主要用途选择来源资料、个人记录、知识整理或可复用模板；人物或来源身份、日期、状态等使用相应现有属性，不冒充阅读主题。已有 type、doc_type、自定义“标签”等字段保持原名，不因本规则批量改写。
- 技术和导入标签按实际用途保留，例如 excalidraw、clippings、movie、teleplay、linker-exclude。原文中的标签、日志局部标记、教程示例和身份未明的旧标签不自动升级为整页主题；规则升级不授权清理全部存量。
- 获授权迁移时保留原文、图片引用、位置、其他属性和既有阅读主题，只增加核实后的主题链接；先核验材料已进入目标视图，再移除本批同义 tags。重复与待核条目不自动接入正式视图，模板不预填具体主题或泛化内容标签。

属性示例：

```yaml
阅读主题:
  - "[[Areas/思维与学习/沟通|沟通]]"
内容类型: 个人记录
```

嵌入主题页的 Base 沿用已验证写法：`file.ext == "md"` 与 `list(note["阅读主题"]).contains(link(this.file.path))`。用页面关联筛选材料，不按文件夹猜主题；默认只显示资料名，类型混合且有阅读价值时再按页面属性分组。静态重建查询结果与实际渲染分别核验、分别报告。

## 小节与稳定引用

- 标题具体、可辨认，尽量在本页唯一；同名标题确有必要时，用包含上级标题的链接消除歧义。沿用目标页层级并逐级递进，不固定所有子内容为 H3，不因出现 H4 就拆页。普通追加保留既有标题与锚点。
- 小节开头提供必要的内容定位与适用条件，保留能理解它的上下文；不为将来可能拆页而重复整篇背景。真正提取时再补足离开父页所需的说明与来源。
- 需要稳定段落引用时才添加本文件内唯一的块 ID，使用英文字母、数字和连字符；保留既有和导入管理的 ID。普通段落可在行末添加，列表、引用、表格等结构块按 Obsidian 块语法处理。
- 标题与块都可被其他页面链接、嵌入，无需仅为引用建文件。块 ID 可减少标题改名的影响，但引用仍包含文件路径；移动内容后需核验原引用，不能把块 ID 当作跨文件自动重定向。

## 已授权拆分与合并

- 先确定内容边界和目标页，读取受影响的文件链接、标题路径、块引用及嵌入，识别属性、附件与来源依赖；备份和并发检查遵循主流程。只处理本次授权范围内的正文，不把复核信号视为自动重组许可。
- 拆分时在原位置保留需要兼容的同名标题及其上级层级，放入新文件链接；迁移的块引用要更新到实际目标，或在原处保留明确的兼容入口。旧标题嵌入和整页嵌入若仍需呈现正文，应核实是否改为对应的新内容嵌入，不能仅验证链接可点击。
- 可用 Note Composer 提取选区或合并，也可按同等约束编辑本地文件。提取默认用新文件链接替换选区，不保证保留选区内的旧标题或块锚点；执行后逐项核验，不把插件操作成功视为旧引用全部有效。
- 合并时保留来源、日期和必要上下文；原文件属性、别名若不能准确表示父页，应按用途保留在合入的小节或另行处理，不机械提升为父页属性。处理旧文件链接及其标题、块和嵌入引用，再按授权处理原文件；仍有无法核验的依赖时保留兼容入口并说明。
- 失效历史导航与原始内容分别处理：已授权清理的旧链接清单只保留在库外备份，不为保留历史而塞回主页、折叠区或新建空文件；没有授权则报告并保持原状。有效旧链接与锚点仍按上述步骤兼容。
- 回读原位置、目标正文及受影响的引用，确认内容无遗漏或意外重复、锚点解析正确、嵌入仍表达预期内容。仅核验源码时明确未检查实际显示。

## 事实、来源与适用边界

- 区分资料明确记载、用户经验和 AI 解释或推断，用自然语言在需要处标明身份；不要求所有段落显示证据等级。
- 把影响使用的条件放在相关结论旁：例如软件版本、操作系统、配置、时间或项目阶段。单次成功、故障或个人体验不能直接写成普遍规律；理论解释不能替代实际验证。
- 命令、参数、数值、单位、引用原文及验证状态必须依据可读材料；看不清或未提供就限定对应疑点，不猜测补齐。归属明确的资料可以照常保存，局部不确定性不扩大为整页警告。
- 多个结论共用来源时可集中说明；不同来源、冲突和关键推断就近标注。出处按需要保留文件名、作者、版本、原始日期、URL、页码、图号或时间戳；上传或获取日期不能替代材料版本。
- 原图、原始文件及来源链接保留证据价值，OCR、摘要和整理稿不能代替原件。实际分析范围有限时说明范围，不声称完整阅读；只有全文转录确有用途或用户要求时才逐行整理。

## 按内容选择表达

可参考以下顺序，缺少的内容省略，不作为必填模板：

| 内容 | 可用组织顺序 |
|---|---|
| 概念与知识 | 核心解释 → 如何理解或使用 → 关系、对比或实例 → 必要条件与来源 |
| 方法与流程 | 目的和进入条件 → 有序步骤 → 实际输入输出或验收依据 → 常见问题 |
| 问题案例 | 当前判断与状态 → 现象和条件 → 现场材料 → 已证实或疑似原因 → 实际措施与结果 |
| 个人记录 | 真实事件和时间 → 本人提供的感受或判断 → 已发生的行动及后续信息 |
| 总览与入口 | 简短导读 → 有实际内容的主题入口 → 必要资料链接 |

默认继承本库 Markdown 写法。顺序用编号，并列用列表，同类属性用小表；长叙述用段落或小节。代码块用于代码、命令和字面值，不把普通中文正文包进代码块。提示、图表、公式和图片只在有助理解时使用，保留文字解释与可追溯依据，不添加装饰性占位内容。

图片紧邻对应步骤或现象，图注交代必要视角、标记、状态和来源。关键条件和结论保持可见，不依赖颜色、并排布局或折叠才可理解；长表和复杂关系优先保证纵向阅读顺序。

## 阅读验收

提交前通读实际新增内容及相邻正文：开头能否知道主题和用途；内容是否连贯、有可复用增量；是否重复或打断旧知识；来源能否追溯；经验和推断是否保持身份；限制是否随结论可见；图、图注、链接及步骤是否对应。

先修正含混、遗漏和重复，再考虑样式。文件和引用检查由主流程执行；仅核验源码时，不声称已在 Obsidian 或手机上完成视觉验收。
