# 记录整理为日志

把用户确实提供的经历、观察、想法与计划整理成日后能读懂的记录。默认沿用用户使用的语言（如中文），理解含义后重新组织表达，直接交付日志正文；短记录保持简短，复杂材料按事件展开。格式应帮助记录，不要求用户先填表。

默认采用干净、精炼的书面语：按含义重写，允许换词、重组语序、拆合句子与合并重复意思，不逐句缩写。优先选用准确、简练的词语或常用成语，能一次说清就不重复解释；若原文是在澄清措辞，按澄清后的意思表达。独立事件、有意义的感受、原有立场与关键限定仍保留。

以含义忠实为前提，尽量用少量自然文字完整表达。精炼不等于少记事情，也不等于保留每个原句；避免口头赘词、刻意文学化和公文套话。用户指定的文风与详略优先，具体改写方式见格式约定。

**日志的价值在于日后可信：只写材料支持的内容，不确定就标出来。** 润色或调整文风只改变表达，不改变事实、归属与确定程度。

## 适用边界

- 适用于“发生了什么、做了什么、观察到什么、当时怎么想、还有什么未完成”的记录整理。已有原稿可润色、重组、合并重复表述，但保留实质信息、确定程度与立场。
- 资料摘录、文章和知识点本身不等于个人经历。只做来源摘要，或在用户要求学习日志时记录其明确提供的学习活动；阅读行为与掌握程度分开。
- 计划、提醒、建议可以作为日志内容；不会因此创建任务、日程或提醒。用户另有行动要求时再处理；若已安装 `content-to-tasks`，可承接任务整理；未安装时先交付 Markdown 行动清单，需要外部操作时说明限制。
- 故障排查与实验的人工记录适用；原始系统日志仅作为证据。纯粹的报错诊断、运行日志格式设计或监控不由本技能接管。
- 本技能负责整理表达。保存、发送、发布、跨应用同步只执行明确授权覆盖本次材料的操作；“整理成日志”本身不授权外部写入。

## 先判断，再组织

1. 确定用户要新建记录、补记、更正、合并，还是周期回顾。默认根据本次材料输出一份整理稿。能保留原文或带标注继续，就先交付，不为缺字段提问。仅当歧义阻塞已授权写入，例如日期决定写到哪天、目标位置或修改范围不明确时，问一个关键问题；可独立完成的部分继续整理。
2. 从材料中辨别事件、对象、时间、行为、观察/结果、判断、计划与来源。只保留有内容的部分，不为填满模板追问或制造空字段。
3. 按连续事件组织。一个事件的多次尝试保留在一起；无关事项拆成小节或条目。跨日期的材料保留各自时间，用户要日记时再按天汇总。
4. 输出本次日志前读取 [日志格式约定](references/formats.md)；本次任务已读且规范未变时可复用。选择最轻的可读格式：随手记录通常只需标题与一段话；工作和会议可用短列表；排查、实验及状态变化需要保留过程与证据。多场景或混合输入时读取 [场景选择与示例](references/scenarios.md)。
5. 将信息重新组织为精炼成稿，合并重复含义，再对照源材料检查时间、对象、数值、否定、因果、完成状态、来源与遗漏。省去可由语境明确的主语与解释；若继续缩短会改变理解或让句子难读，就停止压缩。用户只要成稿时，不附整理思路、打分或例行说明。

## 默认输出骨架

默认使用“日期＋正文”。短记录直接写一段话；主题有检索价值或材料较复杂时，再在标题中加入主题或按事件分条，不另添“日常记录”等泛化标题。以下为虚构的排查记录示例：

```markdown
## 2026-10-11｜同步失败排查

- 现象：同步失败。
- 尝试：重启应用，仍未恢复。
- 当前状态：未解决，原因待确认。
- 后续：计划 2026-10-12 继续检查。
```

只保留有内容的项，不把示例的栏目和事实套进所有日志。用户指定的篇幅、文风或既有记录格式优先。

## 事实与编辑边界

- 可以改换措辞、重建句式、调整叙述顺序、修复明显转写错误、补足上下文唯一确定的指代；保留原有时间、因果与转折关系。姓名、数字、单位、版本、术语、明确要求保留的原话与错误码仍准确，不靠猜测修正。
- 图片、音频或文件须先实际读取可访问内容；无法辨认的片段保留不确定性，不根据文件名或上下文补写。记录主体由来源确定：旧聊天、截图或转述的说话者不明时，用“原记录中提到”等归属表达，不自动改成用户的第一人称经历。
- 保留“可能、约、暂时、还没、据说、我觉得”等限定表达的含义，可用等义措辞，不机械保留原词。“做了某事”不等于“有效”，“一次成功”不等于“稳定解决”，“讨论过”不等于“已决定”。没有说明结果时，不补写成功、失败或结论。
- 区分亲历/观察、他人说法、个人感受、推测、决定和未来行动。用自然措辞表达即可，例如“同事反馈”“我怀疑”“计划”；不必给每句话加证据标签。
- 不确定信息优先就近内联，例如“约 3 公里”“发言人未明确”“日期基准不明”。关键日期、对象归属或结论仍可能被误读时，在日志正文外加一句简短提示；不重复正文已清楚表达的限定。提问仍仅限于阻塞已授权写入的歧义。
- 不新增动机、情绪强度、诊断、责任归属、承诺、负责人、截止日期或工作量。个人日志保持原有记录视角与有意义的情绪，语境明确时可省略“我”等主语，不美化成汇报口吻；会议记录不把他人陈述改成记录者的亲历。
- 日志中已有的计划照实保留。AI 新提出的分析或建议只在用户要求时给出，并明确置于“补充建议”等独立部分，不混入历史记录。
- 用户明确指出录入或转写笔误时，直接按其确认内容修正，不将笔误包装成事实演变。事实后来变化、判断修订或既有正式记录的事实更正，则保留必要的历史与来源，标明新进展或更正；不能仅凭“写错了”猜测是哪一种。保留影响理解的失败尝试、反复和未解决事项。
- 有关人物与对象只使用材料支持的名称或代称。避免从个别记录概括人格、长期偏好或健康状况。密码、访问令牌等不复制进整理稿，可保留必要的脱敏说明；正常记录细节不擅自删减。

## 时间与状态

- **发生时间与整理时间分开。** 已知发生日期用 `YYYY-MM-DD`；仅有月份、时段或大概时间时保留原精度。整理当天不自动成为事件日期，不为记录补上虚构时分秒。
- 用户此刻直接说“今天/昨天”时，可按当前会话日期与用户时区换算。粘贴的旧聊天、附件或历史摘录应优先使用其来源日期；没有可靠基准就保留相对时间并注明基准未明。跨时区、午夜或日期歧义先标注；只有它阻塞已授权写入时才询问。
- 区分完成、部分完成、进行中、受阻、未开始与待验证；根据证据表述，不机械给整篇日志一个状态。尝试后的观察、暂时恢复与最终解决分别记录。计划执行时间与实际发生时间不混用。
- 对同一事项的后续记录，明确是新进展、复发、更正还是重复输入。周期回顾以已有日志为依据，不把重复记录累计成多次成果；没有记录的一天不推断为没有活动。

## 便于后续 AI 读取

- 默认交付有稳定结构的普通 Markdown：可检索主题、可靠时间、明确对象与状态。机器导入与元数据按已读取的格式规范启用。
- 一条记录尽量能脱离当前聊天独立理解。将上下文明确的“那个问题、后来好了”改成具体对象与结果；指代不能确定时保留歧义。
- 保留原有编号、版本、单位、文件名和可用来源链接。多来源或会影响结论的来源就近标注；同一人的简短口述不重复添加来源套话。
- 关联同一事件时沿用已有名称与记录 ID；新的 ID 仅在实际保存或用户要求时建立。标签沿用已有体系，仅在有检索价值时少量使用，不默认给每篇添加泛化标签。
- “适合 AI 阅读”通常意味着语义清楚，不意味着字段越多越好。仅在用户要求机器导入、批量处理或目标系统确有要求时启用结构化格式；缺失信息按约定省略或置空。

## 保存与续写

默认只输出。既定目的地仅指用户在本次对话中明确指定的位置，或用户维护的已安装归档 skill 明确定义的默认目的地；它只回答“保存到哪里”，不自动授权保存。只有明确保存授权覆盖本次材料时才执行，不能凭空间列表、可用凭据或以前任务的目的地自动写入。

实际保存前读取 [保存与外部技能适配](references/storage.md)。已有明确目的地就沿用，不重新争论归属；日期、位置或修改范围阻塞写入时才询问。若所需外部技能或连接不可用，交付 Markdown 整理稿并说明尚未保存；本地文件操作不要求安装归档技能。

向已有日志追加或更正前，读取相关日期/事件的现有内容，核对重复、排序、来源和引用。追加不等于重写历史；修改范围以用户请求为准。保持既有格式，必要时用补记、更正或后续进展连接上下文。写后核实实际内容与目标位置；未保存或无法验证时如实说明。

调整本技能或做回归检查时使用 [验证用例](references/validation-cases.md)，普通记录整理不必读取。
