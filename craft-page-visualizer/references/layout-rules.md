# 布局规则

每个元素至少需要正确管理 `x` / `y` / `width` / `height`；连线还可能用到 `points`。**不要随机摆放元素，必须先计算布局，再调用 API。**

## 栅格与默认节点尺寸

默认使用 8 点栅格：坐标、宽高、内边距和间距尽量对齐到 8 的倍数。允许为几何居中做小幅偏移，但不要每个节点使用一套随意数值。

可根据文字长度动态调整，以下是基础值：

| 节点类型 | width | height |
|---|---|---|
| 核心主题 | ≈ 260 | ≈ 100 |
| 一级节点 | ≈ 220 | ≈ 80 |
| 二级节点 | ≈ 190 | ≈ 70 |
| 辅助节点 | ≈ 160 | ≈ 60 |

如果内容明显更长，再按比例增加宽高，避免文字溢出或被截断。

上述尺寸适用于只有一两行短文字的简单节点。包含“标签 + 标题 + 摘要”的知识卡片默认宽度约 480，允许 320～760；同层卡片优先等宽，高度根据中文换行动态计算。具体卡片结构与变体见 `card-design-system.md`。

## 中文文字尺寸

- 标题最多 2 行，摘要最多 3 行；超出时先压缩内容，再考虑拆节点。
- 中文、全角标点约按 1 个字宽计算；ASCII 小写约 0.52，数字与大写约 0.62，空格约 0.35。
- 正文默认 18，最小不低于 16；不要通过不断缩小字号解决溢出。
- 文字框高度必须按 `行数 × 字号 × lineHeight` 计算，并预留上下内边距。
- 优先调用 `scripts/craft_whiteboard_design.mjs` 的动态排版，不重复临时实现。

## 节点间距

- 横向间距：120～220
- 纵向间距：70～140

避免出现 `nodeA.right + margin > nodeB.left` 这种情况导致节点重叠。写完布局后要过一遍检查有没有重叠。

同一视觉组内部采用较小间距，组与组之间采用较大间距。不要只靠背景色区分分组；间距本身也要表达层级。

## 连线路径

- 流程图、时间线和系统图优先使用直线或正交折线。
- 连线从卡片四侧锚点出发，先经过留白通道，再进入目标锚点。
- 避免跨越多个无关卡片的长对角线，也不要让箭头穿过文字。
- 多行时间线可使用蛇形布局；必须标明阅读方向，相邻行之间只保留一条过渡线。
- 复杂连线先绘制，再绘制卡片和文字，确保 z-order 为：背景 → 连线 → 形状 → 文字。

## 各图形类型的布局方向

**思维导图**：推荐中心辐射式。

```text
                    分支 A
                       │
                       │
分支 B ─────── 核心主题 ─────── 分支 C
                       │
                       │
                    分支 D
```

分支很多时，优先左右分布，不要让所有节点堆在一侧：

```text
         A1 ← A
              \
B2 ← B ─── 核心主题 ─── C → C1
              /
         D1 ← D
```

**流程图**：默认自上而下（Top → Bottom）：

```text
Start
  ↓
Step 1
  ↓
Step 2
  ↓
Decision
 ↙      ↘
A        B
```

如果流程步骤很多、纵向会拉得过长，可以改用自左向右（Left → Right）。

**系统结构图**：

```text
输入层
 ↓
核心系统
 ↓
子系统
 ↓
输出
```

或者中心 + 分支的形式：

```text
           Main System
               │
     ┌─────────┼─────────┐
     ↓         ↓         ↓
 Module A   Module B   Module C
```
