# 专业轻量卡片设计系统

当白板包含 3 个以上卡片，或用户要求“更美观、重排、优化视觉”时读取本文件。目标不是增加装饰，而是用稳定的卡片构成、字体层级和语义颜色，让用户更快识别主干。

## 默认视觉方向

默认使用 Apple 启发的“编辑型轻量卡片”：清晰的深色文字、可辨认的边界、低饱和分类色和三级强调。普通卡片不默认添加左侧色条和胶囊边框；这些组件只留给核心、分类锚点、风险或必要状态。克制不等于低对比，缩略总览下仍应分辨主次和分组。

卡片结构：

```text
  阶段 / 年份
  卡片标题
  一到三行摘要
```

- 左色条只表达关键核心、风险或特殊状态，宽 4；普通节点不画。
- 标签只承载年份、阶段、状态或很短的分类，默认使用无边框元数据文字。
- 标题最多 2 行；摘要最多 3 行。超过时先压缩内容，不要无限增高。
- 卡片内部左对齐；只有白板主标题、单独结论或极短节点才居中。

## 卡片变体

一个白板通常使用 2～3 种变体，不要把全部变体同时堆上去。

| variant | 用途 | 处理 |
|---|---|---|
| `hero` | 核心主题、唯一主结论 | 主色浅背景、较粗边框、标题最大 |
| `standard` | 普通知识节点 | 白底、1px 灰边框、无色条 |
| `milestone` | 时间线节点、阶段节点 | 白底，年份或阶段做无边框元数据 |
| `risk` | 风险、故障、阻塞 | 暖色浅背景；只在真实风险上使用 |
| `conclusion` | 结论、措施、完成状态 | 绿色浅背景；避免把普通节点画成结论 |
| `muted` | 补充、证据、待确认 | 淡灰、低对比；不参与主要阅读路径 |

重要性用 `hero / standard / muted` 表达，语义用 `risk / conclusion / milestone` 表达。不要靠“每个节点一种颜色”制造层级。

## 三级对比阶梯

每张白板都必须能读出三个层级，而不是只有“有颜色 / 没颜色”：

| level | 用途 | 视觉处理 |
|---|---|---|
| Primary | 唯一核心主题或关键判断 | `hero`、2px 强边界、浅色面、窄色标、最大标题 |
| Secondary | 主要分类、关键步骤、主要风险 | 1px 可见边界；可使用低饱和分类色或语义色，标题比正文明显 |
| Tertiary | 资料、注释、共同项、辅助说明 | `muted`、中性灰面、无色标、最低对比但文字仍清晰 |

先用位置、尺寸和留白确定层级，再用色彩加固。缩略预览中若 Primary 与普通卡片看起来一样，视为验收失败。

## 分类色与语义色分工

渲染器的 `tone` 表示识别类别或语义家族，`variant` 表示重要性/状态。两者不要混为一谈：

- `tone: "primary"`：主线、焦虑列、信息类。
- `tone: "purple"`：第二对比对象、抑郁列或另一知识类别。
- `tone: "success"`：行动、措施、求助、完成。
- `tone: "warning"`：注意、共病、风险。
- `tone: "danger"`：仅限立即危险或不可逆错误。
- `tone: "neutral"`：重叠项、资料和低优先信息。

`tinted: true` 使用低饱和浅色面，`showAccent: true` 增加 4px 窄色标。分类色必须同时配合标题/标签和空间分组，不能只靠颜色区分。一个白板通常不超过 4 个非中性色家族。

## 默认设计 Token

- 8 点栅格；坐标、间距和尺寸优先对齐到 8 的倍数。
- 卡片宽度默认 480，允许 320～760；同一行尽量保持相同宽度。
- 卡片内边距：横向 24，纵向 20。
- 卡片圆角使用 Excalidraw `roundness.type=3`。
- 正文最小字号 16；默认标题 24、摘要 18、标签 16；核心标题 28，白板标题 42。
- 卡片横向间距 120～200，纵向间距 80～144。
- 默认边框 `#C7C7CC`；正文 `#34343A`；弱化文字 `#636366`。边框与浅色面必须在缩略预览中仍可辨认。

主色、成功、风险等具体颜色集中在 `scripts/craft_whiteboard_design.mjs` 的 `APPLE_EDITORIAL_TOKENS`；兼容名 `PROFESSIONAL_TOKENS` 指向同一配置。如需项目色，可覆盖 token，但一张白板的非中性色通常不超过 4 种。

## 中文排版

不要用字符数直接等同像素宽度。中文、全角标点按约 1 个字宽；ASCII 小写按约 0.52、数字和大写按约 0.62、空格按约 0.35 估算。

处理顺序：

1. 先压缩摘要，删除重复主语、套话和可从结构推断的连接词。
2. 再用卡片宽度和字号计算换行。
3. 标题超过 2 行或摘要超过 3 行时截断并给出视觉审计警告。
4. 若被截断内容本身重要，拆成两个知识节点；不要缩到 16 以下。

## 布局层级

- 白板只设一个最强标题或核心主题。
- 一级模块默认使用“章节标题 + 细分隔线”，不再使用通栏圆角 Section Band。
- 大多数卡片保持白底；只给核心、风险和结论使用浅色面。
- 同一层级的卡片保持统一宽度、内边距和标题字号。
- 连接线先走留白通道，再进入卡片锚点。流程、时间线优先使用直线或正交折线。
- 多对一或一对多关系只保留一套表达：分组、脊柱或扇出三选一，不同时绘制总线、落线和扇出线。

时间线如果跨多行，使用蛇形阅读时必须明确写出阅读顺序，且相邻行只用一条过渡线连接。不要为了“串联”画跨越多个卡片的长对角线。

## 推荐渲染器

使用 `scripts/craft_whiteboard_design.mjs` 构造元素，再交给稳定写入器。渲染器提供：

- `createWhiteboardDesign()`：统一 ID、Excalidraw schema、8 点对齐和设计 Token。
- `card()`：六种卡片变体、动态高度、中文换行和锚点。
- `boardTitle()` / `section()`：统一标题与弱分区。
- `arrow()` / `orthogonalPoints()`：绝对坐标连线和正交路径。
- `audit()`：重复 ID、无效尺寸、卡片重叠、字体过小、文本截断和颜色过多检查。

最小用法：

```js
import {
  createWhiteboardDesign,
  orthogonalPoints,
} from "./scripts/craft_whiteboard_design.mjs";

const board = createWhiteboardDesign({ runId: "project-20260824" });
const a = board.card({
  id: "input",
  x: 80,
  y: 240,
  variant: "standard",
  tone: "primary",
  tinted: true,
  showAccent: true,
  eyebrow: "输入",
  title: "需求与约束",
  summary: "提取页面中的目标、边界和关键条件",
});
const b = board.card({
  id: "result",
  x: 760,
  y: 240,
  variant: "conclusion",
  eyebrow: "输出",
  title: "可编辑知识图",
  summary: "保留主干、真实关系与关键结论",
});
board.arrow({
  id: "input-result",
  points: orthogonalPoints(a.anchors.right, b.anchors.left),
});

const audit = board.audit();
if (!audit.ok) throw new Error(audit.errors.join("\n"));
// JSON.stringify(board.toJSON()) → craft_whiteboard_write.mjs --elements
```

## 视觉验收

API 字段校验成功不等于视觉合格。提交前至少确认：

- 3 秒内能找到核心主题。
- 标题没有超过 2 行，摘要没有超过 3 行。
- 卡片不存在重叠，内边距与宽度在同层保持一致。
- 分区背景弱于卡片，卡片弱于核心主题。
- Primary / Secondary / Tertiary 三层在缩略总览下仍然明显。
- 暖色只用于风险或转折，绿色只用于结论或措施。
- 普通卡片没有重复色条与胶囊边框；章节没有通栏圆角底板。
- 连线没有穿过文字或无关卡片。
- 非中性色不超过约 4 种；没有大面积高饱和背景。
- 只看白板即可复述主线，而无需逐字阅读所有卡片。

`audit()` 能覆盖结构化检查，但不能完全替代视觉观察。对于复杂白板，写入后应打开白板或使用可用的页面截图能力检查实际渲染，再对同一个 whiteboard 使用 PUT 修正。
