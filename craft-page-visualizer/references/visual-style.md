# 连线语义与视觉风格

## 连线代表真实关系，不是装饰

`A → B` 常见含义：流向、步骤、因果、数据传递、能量传递、调用关系。
无方向关系用 `A — B`。

**如果关系不明确，不要强行连接。**

## 不确定关系的处理

如果原文不能证明 `A → B` 这个关系，不要擅自生成确定连线。可以：
- 用 `A --?--> B` 这种虚线/问号样式表示不确定
- 或者添加一个"待确认"标签

如果实在无法可靠表达，宁可不画这条线。这是硬性要求，不能为了图好看而编造关系。

## 连线标签

当关系无法仅靠箭头表达清楚时，可以加简短标签，例如：供电、包含、导致、调用、输入、输出、属于、依赖、转换、同步。避免用长句作为连线标签。

## 视觉语义（颜色与强调）

如果当前 API/schema 支持样式属性，可以建立轻量视觉层级，颜色只负责表达语义，不是装饰：

| 元素类型 | 视觉处理 |
|---|---|
| 核心主题 | 最突出 |
| 一级节点 | 中等强调 |
| 普通节点 | 低强调 |
| 风险/问题 | 暖色弱强调 |
| 结论 | 独立强调 |
| 待确认 | 弱化 |

**不要把白板做成五颜六色的信息海报**——每个节点一种颜色、大面积高饱和色，都是要避免的。

## 默认卡片外观

卡片默认使用白底和 1px 细灰边框，不默认添加左侧色条。核心、重要风险可以使用 4 宽的语义色条；章节默认使用文字和细分隔线。核心、风险和结论节点可以使用浅色面；普通节点不要整卡着色。

默认语义色：

| 语义 | 颜色角色 |
|---|---|
| 主线 / 核心 | 蓝色 |
| 结论 / 措施 / 完成 | 绿色 |
| 风险 / 转折 / 注意 | 橙色或红色 |
| 分类 / 阶段 | 紫色，可选 |
| 补充 / 待确认 | 灰色 |

一张白板的非中性色通常不超过 4 种。颜色负责说明语义，重要性主要通过尺寸、位置、边框和留白表达。

卡片内文字默认左对齐。主标题、单独结论或极短中心节点可以居中；不要把长摘要居中排版。详细 Token、卡片变体和渲染器见 `card-design-system.md`。

## 字体层级

- 白板主标题约 32～40。
- 核心卡片标题约 26～30；普通卡片标题约 22～24。
- 摘要约 17～19；标签约 16。
- 同一层级使用相同字号，不用粗细、颜色、大小同时强调同一件事。
- 标题最多 2 行、摘要最多 3 行。若信息仍放不下，压缩或拆节点。

## 整体视觉风格

目标：简洁、克制、现代、清晰、轻量，高信息密度但不拥挤。更接近"专业知识图 + 现代思维导图 + 轻量系统架构图"的观感。

要避免：
- 大面积高饱和色
- 过多装饰
- 多种字体风格
- 每个节点一种颜色
- 节点里塞大段文字
- 密集交叉线
- 伪阴影（复制多个偏移矩形）和无语义装饰图形

## 避免"蜘蛛网"

如果节点之间存在大量 many-to-many 连接，不要把所有边都画出来，只保留对理解最重要的关系。次要关系可以通过分组、空间邻近、节点归类来隐性表达，而不是显性连线。

不要同时绘制“多条扇出线 + 一条总线 + 多条落线”。多对一或一对多结构优先改为单条分组脊柱，或直接依靠统一标题、对齐和邻近表达。
