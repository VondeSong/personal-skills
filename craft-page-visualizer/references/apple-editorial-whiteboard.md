# Apple 风格的编辑型白板

当用户说“界面乱、UI 不好看、色彩不好看、参考 Apple、重新排版”时读取本文件。这里借鉴的是 Apple 的信息设计原则，而不是复制某个产品界面：秩序、清晰、克制、语义色、稳定节奏。

## 先修层级，再修皮肤

视觉优化按这个顺序进行：

1. 明确唯一主焦点，次级焦点最多两个。
2. 确定一条主阅读路径；次要内容靠分组与邻近表达。
3. 删除没有语义价值的卡片外框、横条、色块和连线。
4. 统一标题、正文、元数据的字号与间距。
5. 最后才调整圆角、边框和颜色。

不要用更多组件掩盖结构问题。

## 默认视觉语言

- 画布：白色；辅助表面 `#F2F2F5`。
- 主文字 `#1C1C1E`；正文 `#34343A`；弱文字 `#636366`。
- 分隔线 `#D9D9DE`；普通卡片边框 `#C7C7CC`、1px。
- 主线蓝 `#0A66FF`；分类紫 `#9B51E0`；结论绿 `#2EAD4A`；注意橙 `#F59E0B`；严重错误红 `#FF3B30`。
- 一张图只有一个主强调色。语义色只出现在标签、小色条、关键连线或极浅色面，不铺满整张白板。
- 卡片圆角保持一致；不做拟物阴影，不重复矩形制造阴影。

## 减少卡片依赖

不是每段内容都需要“白底 + 圆角 + 描边 + 左色条 + 胶囊标签”。

- 主标题：默认使用文字与细分隔线，不放进粗边框大卡片。
- 章节：使用小标题、说明和一条细分隔线，不使用通栏灰色圆角横条。
- 普通节点：白底或无底、1px 浅灰边框；默认不画左色条。
- 年份/阶段：用小号元数据文字；只有需要强交互暗示时才使用胶囊。
- 核心节点：允许极浅蓝面和 2px 主色边框，全板通常只设一个。
- 风险节点：允许极浅橙面；只有最重要风险保留橙色窄条。
- 结论节点：允许极浅绿面；同一排多个结论时不要每张都用高饱和边框。
- 资料卡：使用灰色辅助表面或纯文字链接，视觉权重必须最低。

## 克制不等于低对比

如果缩略总览中所有卡片都变成近似白色的小块，说明设计过度弱化。此时按顺序修正：

1. 先把标题/章节/卡片标题的字号与文字明度拉开。
2. 再强化 Primary 的浅色面、2px 边界和窄色标。
3. 给持续出现的对比类别分配固定的低饱和 `tone`，例如蓝色 A、紫色 B、中性灰共同项。
4. 行动与解决方案统一使用绿色；风险统一使用橙色；红色只给立即危险。
5. 不要通过恢复所有卡片的彩色描边来解决对比不足。

颜色之外必须保留标签、列位置、章节标题等第二识别通道，以支持灰度和色觉差异场景。

## 连接线降噪

- 主路径使用主色，宽 2～2.5；次要关系使用 `#8E8E93`，宽 1～1.5。
- many-to-one / one-to-many 优先用分组标题、对齐和邻近表达。
- 不画“总线 + 多条落线 + 多条扇出线”三套关系。通常只保留一条分组脊柱。
- 连线数量超过知识节点数量时先删线，而不是换颜色。
- 暖色连线只表达风险、阻塞或负向结果，不承担整张图的普通结构。

## 间距与信息密度

使用 8 点栅格，常用节奏为 8 / 16 / 24 / 32 / 48 / 64。

- 同组卡片间距小于组间距。
- 节点横向间距建议 96～160，纵向间距 64～120。
- 卡片内部标题与摘要间距 8～12；标签与标题间距 8。
- 总览缩放下仍不可读的小字应删减或拆层，不要缩得更小。
- 每个卡片只保留一条标题和 1～2 行摘要；标签也不小于 16，细节放回原页面。

## 截图复盘清单

- 眯眼看时，是否仍能看到唯一主焦点和主路径？
- 是否有超过一半的节点使用彩色边框或彩色填充？若是，降低颜色。
- 是否每个章节都被一个大横条包住？若是，换成标题 + 分隔线。
- 是否每个卡片都有色条和胶囊？若是，只给关键语义保留。
- 是否存在总线、扇出线和落线同时出现？若是，保留一种。
- 是否因为空白太大而把内容分散到屏幕四角？若是，收紧组内间距。
- 是否因为所有卡片同尺寸同色而没有重点？若是，使用位置、尺寸和留白建立层级。
- 缩略总览中是否能区分 Primary、主要分类和资料区？若不能，增强文字、边界和低饱和分类色，而不是增加颜色数量。

渲染器的默认 `PROFESSIONAL_TOKENS` 已指向 `APPLE_EDITORIAL_TOKENS`。对于旧白板，更新同一个 whiteboard，不要因为重排而重复新建。
